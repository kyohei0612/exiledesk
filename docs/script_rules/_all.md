# POE2Tube 台本ルール集 (Claude が台本を書く前に必ず読む)

対象: PoE2 のストーリーをクリアしたばかりの初心者に向けた、ずんだもん × 四国めたんの掛け合い解説。
数字と MOD 名は **クラフトステージの結果 JSON** から取り、台本側で作らない。

## 0. シリーズの方針 (2026-09-28 kyohei)

**PoE2 の 1.0 正式リリースに向けた「基礎知識まとめ」シリーズ。** 1 本ごとに 1 つの基礎 (クラフト・カレンシー・装備など) を、
アクト中〜エンド序盤の人が「1.0 までに知っておけば困らない」形でまとめる。
- 導入で「1.0 が来る前に基礎を固めておこう」の位置づけに軽く触れてよい
- 1.0 の発売日・新要素・仕様変更は断定しない (分からない事は言わない)
- 次回予告はしない (シリーズでも 1 本で完結させる)

## 1. 出力の形 (poe2tube-script/1)

`VideoScript` (src/poe2tube/script/model.py) の JSON をそのまま返す。前後に説明文を付けない。

```json
{
  "schema": "poe2tube-script/1",
  "title": "【PoE2 初心者】...",
  "target_seconds": 60,
  "result_file": "<結果 JSON のリポジトリ相対パス>",
  "sections": [
    { "name": "導入", "target_seconds": 10, "lines": [
      { "speaker": "zundamon", "emotion": "troubled", "text": "...", "speech": "...", "scene": { "kind": "talk" } }
    ]}
  ]
}
```

- `speaker`: `zundamon` (質問役) / `metan` (解説役)
- `emotion`: `normal` / `troubled` / `surprised` / `happy` / `proud` / `sad`
- `text`: テロップ兼セリフ (60 字以内)。`speech`: 読み上げ用の書き換え (MOD → モッド、+9% → プラス9パーセント、数字の読み)。読みが素直なら省略可
- `scene`: 1 行ごとに **必須**。無いセリフは作れない

## 2. 画面 (scene) の決まり

| kind | 使う場面 | 必須フィールド |
|---|---|---|
| `talk` | **基本使わない** (何も出ない画面、kyohei 2026-09-30)。雑談・つなぎ・締めも話題の物を出したまま話す | なし |
| `stack` | 工程の解説。並べる工程 `show_steps` と強調 `step` | `step`, `show_steps` |
| `item` | 工程後のアイテムを大きく見せる | `step` |
| `stage` | 実践 (クラフトステージ)。`step` 手目まで進めた状態 (0 = 開始前) | `step` |
| `cost` | 費用まとめ (初心者向けでは使わない) | なし |
| `tiers` | 1 つの MOD の段の表 (T1〜Tn、必要アイテムレベル、出やすさ)。その実演のアイテムレベルで出る一番上の段が金色 | `mod` (MOD の id か系統、例 `ColdResistance`)。ベースとアイテムレベルは実演から |
| `compare` | 2 つのアイテムを並べて違いを色で (増 = 緑、減 = 赤)。「入れ替えるか」の話に | `step` (左 = 今の装備の実演の手)、`compare_with` (右の実演キー)、`b_step` |
| `dps` | スキルの DPS の内訳 (ベース / MOD / ルーンで増えた分、元素ごと)。「どの MOD が一番火力に効いたか」 | `step` (0 = 白)。実演に PoB の計算 (手順の `pob`) が要る |
| `ttk` | 敵の人形を殴って倒すまでの秒数。2 本並べて競争 (「白 4.2 秒 → レア 2.1 秒」)。DPS より初心者に伝わる | `step` (左)、右は `b_step` (同じ実演の別の手) か `compare_with` + `b_step`、`labels` (例 `["白", "レア"]`)。質問の行は `reveal: false` (秒数を隠す) |
| `hit` | 同じ元素の一撃を耐性違いで受けて、ライフの削れ方を並べる | `step`、`elem` (fire / cold / lightning / chaos)、`res` (例 `[50, 75]`)、`dmg` (無ければ PoB の敵の一撃。付けると「仮の一撃」と出る) |
| `resists` | 装備の組の耐性 4 本の棒。アクトが進むとペナルティで削れる、上限 75% | `resists` (brief の組のキー)、`act` (0 = アクト 1 … -60 = エンド)。質問の行は `reveal: false` (ペナルティ後を隠す) |

- **PoB の数字の画面 (stage の DPS の札・compare・dps・ttk・hit) は、実演の手順に `pob` がある時だけ**。質問の行で DPS を見せたくない時は `show_dps: false` (打つ行 = その手が初めて出る stage では使えない。打つ瞬間に数字が出るので、前の行で聞く)
- `ttk` の質問の行 (`reveal: false`) は競争の前の絵で止まる。答えの行で競争が流れて秒数が出る (動きは約 5 秒。行が短くても動きが終わるまで延びる)
- 答えを隠した行 (`reveal: false` / `show_dps: false`) の次の行で同じ画面の答えを出すと、隠した所から答えが出る動きになる (自動)。画面が変わった行は登場の動き (棒が伸びる・数字が数え上がる) が自動で付く
- セリフにスキル名・ルーン名 (公式日本語) が出ると、その絵が小道具でポップする

- **ネタバレしない** (kyohei 2026-09-29): 画面の変化 (付く・正解が緑になる) は声より先に見せる (動画づくりが自動で声を遅らせる)。答えを問う行では画面に答えを出さない: `tiers` の質問の行は `"reveal": false` (金の段を出さない) にして、答えを言う行で `reveal` を戻す
- `stage` に `focus` (MOD の id か系統) を付けると、その MOD の行だけ金の枠で光る (スポットライト)。「この MOD に注目」「これが当たり」の行に使う

- `highlight`: `added` (付いた MOD を光らせる、その工程で MOD が増えた時だけ) / `rarity` (レアリティが変わった時) / `name` (名前が変わった時) / `step` (工程カード自体)
- **積み上げ**: 工程 1 は `show_steps:[1]`、工程 2 は `[1,2]`、最後は全部。解説が進むほど並ぶ枚数が増える
- **何も出ない画面 (`talk`) は使わない**。雑談・つなぎ・締めの行も、その時の話題の物 (ずんだもんの武器・実演・比べる画面・耐性など) を出したまま話す (kyohei 2026-09-30「基本何も出さない所無くそう」)
- **同じ画像なら、テロップが変わっても画面はそのまま置いておいてよい** (何行続いてもよい、kyohei 2026-09-30)。話題が変わった時に画面を変える
- **情報の画面 (compare / dps / resists / tiers は 8 秒以上、ttk / hit は 5 秒以上) は出したまま話す** (kyohei 2026-09-30「せっかく作った比較画像や DPS があまりにも早く消える」「すぐ消えて何も出ていないのに喋っている時がもったいない」)。
  画面を出したら、その画面の中身をつなぎで話す行を続ける (左右の違い・数字の読み方・どこを見るか)。説明の途中で会話 (talk) の画面に戻さない。
  答えを隠す行と出す行は同じ画面として数える (`lint.info_screen_time` で機械チェック)
- `step` は結果 JSON の `steps[].index` の範囲内。存在しない工程を指さない
- **説明している状態と画面を一致させる**: 白 (ノーマル) の話をしている間は `item` の `step: 0` (使う前の白) を出す。青の話なら青の工程。話と色が食い違うと視聴者が混乱する (2026-09-28 kyohei)

## 3. 構成 (伸びているゆっくり解説の型)

| セクション | 目安 | 中身 |
|---|---|---|
| 導入 | 全体の 15% 以内、**30 秒以内** | 問いかけ / 意外な事実 / 約束 のどれかで「見る理由」を出す。ずんだもんの困りごとから入る。**完成品 (最終工程の `item`) を先に見せてよい** (予告、2026-09-27 kyohei OK)。ただし**完成品に驚かない** (視聴者はまだ MOD の良し悪しが分からないので「うぉー!」にならない、2026-09-28 kyohei)。「作り方の説明」+「付いた MOD のティアを見て装備を替えるか決められるようになる」をこの動画のゴールとして約束する |
| 仕組み | 45% | 工程ごとに PREP (結論 → 理由 → 具体例 → 結論)。1 工程 = めたん 2〜3 行 + ずんだもん 1 行。**知識で終わらせず判断につなげる**: 「どの MOD がどのティアで出たら今の装備と入れ替えを考えるか」の路線で組む (2026-09-28 kyohei)。目安は「考えていい」止まりで、ゲームの仕様のように断定しない |
| 実践 | 30% | クラフトステージで実際に使う。**1 手 = 2 行以上**: ①「○○のオーブを持って、アイテムに使うわね」と宣言 (`stage` の `step` は 1 つ前 = 使う直前) → ②「△△が消えて □□ が付いた」と変わった MOD を名指し (`stage` の `step` はその手)。複数の手を 1 行にまとめない。**使う瞬間は急がない**: 変化を言葉で 1 回なぞる (2026-09-28 kyohei「何の MOD が入れ替わったか分からなかった」) |
| まとめ | 10% | 要点を 3 つ以内で復唱 (ずんだもん) → この動画の内容で締める (めたん)。**次回予告はしない、次回の内容にも触れない** (kyohei 2026-09-28 確定)。代わりに最後は**チャンネルの方針** (PoE2 の基礎を初心者向けにまとめていく、アクト中から始められる事を解説していく 等の大きな話。チャンネルは 1.0 以降も続くので、方針に 1.0 は入れない) と**チャンネル登録・コメントのお願い** (分からない所・知りたい事をコメントで) で締める (kyohei 2026-09-28)。「次回」「次の動画」「お楽しみに」は使わない |

- **1 分 = 約 400 字** (実測: 1.2 倍速 + 話速の揃えで 2,502 字 → 6 分 10 秒、2026-09-28)。`target_seconds` から逆算して総文字数を決める
- 8 分なら 3,200 字前後、6 分なら 2,400 字
- **台本の中で尺を口にしない** (「この 8 分で」等)。実尺は生成後に決まるので食い違う

- **過去の動画で扱った物は、詳しく説明し直さない** (2026-09-28 kyohei)。「前の動画で解説した」と一言触れる程度にして、今回の新しい中身に時間を使う。例: レアリティの色と枠・MOD・ティアの見方・変成 / 増強 / 王者 / 高貴・サファイアの指輪 (前回の「クラフトの基礎」回)。前の動画に触れるのは OK、次の動画 (予告) に触れるのは NG
- **サムネは毎回 0 から、その動画のために考える** (kyohei 2026-09-28「ありきたりなのが嫌」)。型 (make_thumbnail の並び) を使い回さない。動画の一番の見どころ・言いたい事を 1 枚の絵にし、案を 1 行で説明してから作る。作った物は `scripts/thumbs/<name>.py` に残す。**背景は基本白** (kyohei 2026-09-28「暗いね、白がいい」、動画本編の白背景とそろえる)。**文字は他の物 (箱・アイコン・キャラ・別の文字) に被せない** (kyohei 2026-09-28)。**上げる前に必ず kyohei にサムネだけ見せて OK をもらう** (2026-09-28)。文字は単調にしない (行ごとにスタイル・大きさ・色を変える、強調語を一段大きく)
- **クイズは 1 本に 1 問、まとめの前に選りすぐりの物** (2026-09-30 kyohei、章ごとのクイズはやめた)。形は 3 行:
  ① めたん「ここでクイズ。…はどれ？」(`quiz`、選択肢 2〜4、正解は出さない) → ② めたん「3 秒で考えてね。」(同じ `quiz` に `countdown: 3`) → ③ めたん「正解は○○。」(`answer` を付けて正解を緑に、理由を一言)。
  選択肢はカレンシーのキー (アイコン付き) か短い文字 (「T1」「T8」「付ける」「付けない」等、6 字以内)。その章で言った事だけから出す (新しい事を問わない)
- **台本ができたら kyohei と 1 章ずつチェックする** (2026-09-28 kyohei「1 章ごとにチェックが丸い」)。全部を一度に直さない。1 章ごとに「今の問題 → 直した案 (表: 番号 / 話者 / 画面 / セリフ)」を出し、OK をもらってから台本に入れて次の章へ。会話の流れ (前の章からのつながり・驚きの使い方・同じ話の繰り返し) も見る

## 4. テンポと掛け合い

- **解説役 3〜5 行に聞き役 1〜2 行**。聞き役の比率は全体の 25〜50%
- **30〜60 秒に 1 回、軽いツッコミ** (「たった 3 個なのだ！？」)。大爆笑は狙わない、小さなズレで十分
- **一文 40 字以内**。長い説明は 2 文に割る
- セリフの長さをばらつかせる (全部同じ長さは単調)
- 感情の合いの手 (「えっ？」「おお」「本当なのだ？」) でリズムを作る
- 長く同じ画面の時は、小道具 (セリフにカレンシー名・スキル名) や答えを出す動きで変化を付ける

## 5. キャラの口調 (固定、ブレさせない)

| | ずんだもん | 四国めたん |
|---|---|---|
| 役 | 質問役。ストーリークリア後に迷う初心者の目線 | 解説役。PoE2 に詳しい先輩 |
| 語尾 | 「〜なのだ」「〜のだ？」「〜なのだ！」(全行に「のだ」を含める) | 「〜よ」「〜ね」「〜わ」「〜かしら」 |
| 禁止 | 敬語・です/ます、専門用語を自分から言う | 敬語・です/ます、「簡単」「余裕」で突き放す |
| 一人称 | ぼく | 私 |

## 6. 用語と数字

- カレンシー・お告げ・エッセンスの名前は **ゲーム公式の日本語** (結果 JSON の `currency_ja` / `omen_ja`、`price-keys.json`)。「エグザ」「トランス」等の略称は使わない。Exalted Orb は「高貴なオーブ」
- MOD は結果 JSON の `text_ja` の言葉を使う (「見つかるアイテムのレアリティが 9% 増加する」→ セリフでは「レアリティ +9%」のように短くしてよいが、数字は変えない)
- レアリティは 白 (ノーマル) / 青 (マジック) / 黄 (レア) と色で言う
- **クラフトの解説と一緒に、解説している装備 (ベース) の話もする**: どこで・いつ手に入るか、なぜこのベースを選んだか (`_facts.md` の入手時期の表にある事だけ)。視聴者の段階で手に入らないベースを「拾った」と言わない (kyohei 2026-09-28: ニーモニックリングは創生の木限定でアクトでは付かない)
- **DPS・防御の数字は PoB の計算 (結果 JSON の `pob`) だけを使う**。自分で掛け算しない。数字を初めて出す行で、前提 (「同じキャラ・同じスキルで武器だけ替えた時」「普通の敵」「アクト 3 の耐性ペナルティ」等、結果 JSON に書き戻された設定) を 1 回だけ言う (kyohei 2026-09-29「設定は計算の時も解説の時も大事」)
- **記事を参考にした事は、出典を brief の `sources` に残す** (説明欄に自動で載る、kyohei 2026-09-29)。記事の文章をそのまま読まない (自分の言葉で短く)
- 初心者向け回では **値段の話をしない** (2026-09-27 kyohei)。`cost` シーンも使わない
- MOD の枠は **「プレフィックス」「サフィックス」** と言う (ゲーム内表記。「接頭」「接尾」は使わない、2026-09-27 kyohei)。画面のカードでは短く「プレ」「サフィ」
- 専門用語 (MOD、プレフィックス/サフィックス、ティア、ilvl) は初出でずんだもんに聞かせて、めたんが 1 文で言い換える
- 結果 JSON で `applied: false` の手は「ここでは使えない」と正直に扱う。失敗も隠さない

## 6.5 読みと章名カード (自動)

- 読みの直し: 「解呪」は「かいじゅ」と読ませる (`script/reading.py`、テロップはそのまま)。読みを間違える言葉が見つかったらここに足す
- 章名カード (3 秒): その間は声もテロップも出さず、画面はモザイクで章名だけを目立たせる (kyohei 2026-09-30「ネタバレみたいになる」)

## 7. 小道具 (自動)

セリフ本文に公式名 (「変成のオーブ」等) が出ると、そのアイコンが自動でポップする。
**工程を説明する行には必ずカレンシー名を本文に入れる** (略さない)。

## 8. 自己チェック (返す前に)

1. 全行に `scene` がある。`step` は結果 JSON の範囲内
2. `highlight: added` の行は、その工程で本当に MOD が増えている
3. ずんだもんの全行に「のだ」がある。めたんに「です/ます」が無い
4. 一文 40 字以内。総文字数が `target_seconds` × 5.5 字 ± 25%
5. 同じ scene が 3 行以上続いていない
6. 数字・MOD 名・カレンシー名が結果 JSON と一致している
7. 実践で `stage` の `step` が 1, 2, …, 最終 と 1 つも飛ばずに出てくる (1 手 1 行以上)

これと同じ密度・同じ画面の切り替え方で書く。
