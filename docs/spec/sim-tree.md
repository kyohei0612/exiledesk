## ③ 決まり

**大本 (オーナー 10-29、判定の整理)**: ① 箱の判定は箱に描いている中身 (見本の実物) で決める。道から足していく古い数え (道の当たりの狙いを足す・持って着きうる狙い・形の鍵で先に絞る) は判定に使わない。② 手ごとの特別扱いはしない (フラクチャー・カタリストの結果の除外・カオスの外れを親へ、は消す。中身の判定に任せる)。オーナー「そもそも特別仕様にも対応できるように作らないとダメだから特別扱いなんてのはしたらダメよな」。判定は 2 つだけ (S-50b)。作るのはスイッチ judgeOne の下。

書き方: **番号 一文** — 状態 / 出どころ / 確かめ方。状態は README.md の 3 の 5 つの型 (有効 / オーナー OK 済み・本番待ち (スイッチ名) / 仮 (オーナーの OK 待ち) / 未決 / 撤回)。「オーナー OK 済み」は 10-28 夜のスナップ (共有メモ ok-snaps/sim-*.png、オーナー「OK。変性とか増強とかのあの例の枝くらいかな実戦で試すの。、他OKでいいよ」)、出すのは「出して」と見張りの後。食い違う決まりは、オーナーの言葉の日付が後の方に揃え、古い方は撤回 (M の章) にして新しい番号を指す (10-28 深夜オーナー「新しい奴にそろえるように設計図整理だなしっかり」)。

### B. 始まりと ✦

- **S-10 ✦ = 固定してよい印**: 完成の狙いに付ける。付け方は「フラクチャー」ボタンかカードの右クリック (スマホは MOD を押す)。スイッチ clickFracture の下では PC もカードの MOD の行を押すと印を付け外し (右クリックも残す。エミュの M-18 と同じ共通のカード StageItemCard の clickFracture)。 — 有効 (PC のカードを押して付けるのは 仮 (オーナーの OK 待ち、スイッチ clickFracture)) / オーナー 10-20・10-23・10-28「あとスマホと共有でクリックでもフラクチャーできるようにPCも変えてくれ」(エミュの画面を見て。シミュの完成形も同じ揃え方、メモ「グローバルな依頼は全部に」) / 画面 (dev、完成形のカードの P1 アーマーを押す → ✦ 1、もう一度で 0。スイッチを閉じると押しても 0)
- **S-11 ✦ は何個でも**: 付けてもほかの印は外れない。フラクチャーの手は、どの ✦ が固定されても当たり、✦ の無い MOD が固定されたら外れ。エンジンの固定は 1 アイテム 1 つのまま。 — オーナー OK 済み・本番待ち (スイッチ fracMulti)。前の「1 つだけ」(10-26 夜) は撤回 = S-121 / オーナー 10-28「✦ を複数設定してよい」 / 画面
- **S-12 スタートの形は印で決まる**: ✦ あり = ✦ の MOD のどれか 1 つが固定されたレア (外れは木で付ける、START_JUNK 0)。✦ なし = 白 (ノーマル)。スイッチ startCard の下では、PC の木のスタートの箱も結果の箱と同じアイテムカード (レアリティの色の名前の帯・MOD の行、✦ の MOD はフラクチャー) で出す。Lv・✎ の行は上、カードの下に「ベース」・始め方とベースの値段の 1 行・＋MOD、カードを押すと始まりの形の窓 (スマホは前から 1 段目でカード)。 — 有効 (スタートのアイテムカードは 仮 (オーナーの OK 待ち、スイッチ startCard))。10-23 の「固定 1 + 外れ 3」は撤回 = S-122 / オーナー 10-25 (544f1241)・10-28 夜「フラクチャー済みからのやっつがアイテム欄の表示じゃないの違和感ここレアなんかもわからんしスタートもアイテムカードで表示させてくれツリー」 / 画面 (dev、ok-snaps/sim-14-start-card.png: フラクチャー済みから = レアのカード、白から = ノーマルのカード)
- **S-13 始め方の窓 (決めた → ツリーへ)**: (a) フラクチャー済みから / (b) 白から確定フラクチャー / 白ベースから (フラクチャー無し)。違うのは始めの値段だけ。スイッチ fracOne の下では、フラクチャーから始められるのは ✦ がちょうど 1 つの時だけ: ✦ が 2 つ以上なら始まりは白ベースだけ (✦ の印は残し、木の中のフラクチャーの手は S-42・S-43 のまま)。窓は ✦ の一覧と「✦ が 2 つ以上なので白ベースから。フラクチャー済みから始めるなら ✦ を 1 つに」の一言、選ぶ物は無し。スタートの箱の始め方の切り替えも出さない。前の版の ✦ 2 つ以上で「フラクチャー済みから」の木は、開いた時に白ベースから (`start.from` four) に読み替える。 — 有効 (✦ 2 つ以上の扱いは オーナー OK 済み・本番待ち (スイッチ fracOne)) / オーナー 10-26 夜・10-28「フラクチャー複数選択の時点で白ベースにさせるべきだよね…単発のみフラクチャースタートできるようにさせるか」 / 画面 (dev 1440: ✦ 2 つで窓は白ベースからだけ・始まりは白、✦ を 1 つに戻すとフラクチャー済みからへ戻る (自動で替えた時だけ、`TreeStart.autoWhite`)。印無しの窓は先頭の MOD に ✦ + (a) が既定)

### C. 手と結果の箱

- **S-20 打つ手はゲームどおり自由**: 棚・並び・打てない手を出さないのはエミュと同じ (G-03)。ツリーの棚に出さない物: ヒネコラの髪束 (説明も)・聖別・ミラー・神のオーブ・祝福のお告げ・クラフト以外のルーン。錯乱のエッセンスは使えない。 — 有効 / オーナー 10-23・10-24・10-27 / 画面
- **S-21 起こりうる結果を全部箱で出す**: 着いた人のアイテム × その手 (お告げ込み) でエンジンが出しうる結果ごと。お告げで減る・確定なら 1 つ。自動で隠す・外れに入れる物は作らない。まとめる・分けるは人。 — 有効 / オーナー 10-25・10-26「あくまでもツリーは全ての結果を表示して」 / 見張り
- **S-22 ☑ の物だけが当たり**: 手の窓で ☑ (複数可) した MOD ごとに当たりの箱 + 外れ 1 つ (スイッチ junkSide の下では外れは側ごと、S-65)。☑ の無い MOD はそのカレンシーでは外れ MOD (☑ の無い狙いが付いても外れへ、止めない)。 — 有効 (10-27 の (a) は撤回 = S-123) / オーナー 10-27 朝 (メモ feedback-unchecked-is-junk) / 見張り
- **S-22b ☑ を選ぶ手の結果は「持っている狙い + この手の ☑」だけで見る**: 付け足す・入れ替える手 (高貴・カオスなど ☑ を選ぶ手) の結果の分け方は、打つ前に付いている狙いとこの手の ☑ だけで数え、☑ の無い完成形の MOD が付いても外れ MOD (当たりを取らない)。持っていた狙いが消えた人は、☑ の狙いが付いても「狙いが消えた」(エッセンス S-29 と同じ順)。当たりの箱 = 持っていた狙いが残って ☑ が付いた人だけ (正解の形)。前は木の狙い全部で数え、カオスで最大ライフが消えて知性 (☑ 無し) が付いた人は「外れ」、ほかの外れが付いた人は「狙いが消えた」と同じ移り方で枝が割れ、最大ライフが消えて雷耐性 (☑) が付いた人は当たりの箱に入り当たりの見本が最大ライフの無い物になった (木 oWkFcwYX の b14、予約 F)。 — 作った (スイッチ judgeOne、OK 待ち) / オーナー 10-29 深夜「ツリーにうったカレンシーで枝が全然違う 特に正解が出ないとか致命的」 / 画面 (dev 1447、木 oWkFcwYX)
- **S-23 手の窓の既定は狙い無し**: 狙い無し = 結果は「打った後」1 つ (完成の狙いが付いた人もここ。スイッチ junkSide の下では側ごと、S-65)。MOD を押すと狙い無しが外れ、全部外すと狙い無しに戻る。 — 有効 (10-26 昼の「候補に全部 ☑」は撤回 = S-124) / オーナー 10-26 夜「デフォルトは狙い無し」 / 画面
- **S-24 当たりの箱は MOD ごと**: 同じ側でも自動でまとめない。もう持っている狙いがもう一度付く道は数えない。 — 有効 / オーナー 10-26・10-27 夜 (hitNew) / 見張り
- **S-25 当たるまでの手は作らない**: カオススパムオーブの札は無し。当たるまでは「カオス 1 回ずつ + 外れ → 親の箱」で表す。前に保存した当たるまでの手は読めて動き、名前は設定したカレンシー。 — 有効 / オーナー 10-25・10-27 昼 (noSpam) / 画面
