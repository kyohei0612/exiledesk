# 設計図 — デイリークラフトチャレンジ (D-xx)

持ち主: デイリー部長。2026-11-01 に案を書いた (オーナー「一旦土台からもりもりでつくろうか これはデイリー部長任命です」)。
型は `README.md` の「3. 書き方の型」。大本は G-xx。**この紙は全部 `仮 (オーナーの OK 待ち)`** で、作るのは OK の後 (G-20)。番号ごとの状態は OK が出た物から書き替える。
構想の正はメモ craft-challenge の 10-22 の節と daily-brief.md のオーナーの言葉。`docs/craft-challenge.md` の 2 コースの話と「0 時更新・エミュで手で打つ」は 10-22 に置き換えられた古い記述で、この紙が OK になったら「D-xx を見る」の 1 行にする。

## ① この紙の範囲

- 持つ物: デイリーのページの流れ・投稿の導線・挑戦 (時間制限・提出)・順位・サーバーの表の形・デイリーの見た目・スマホの扱い。
- 持たない物 (紙の名前で指す):
  - 箱・手・結果の箱・同じ形・回す・精査の決まり → `sim-tree.md`。**デイリーの木はシミュの木そのもの**で、デイリーで決まりを足さない (D-30)。
  - カレンシーの動き・MOD・確率 → `engine.md` (G-06)。
  - 共通の部品と挙動 → `shared-ui.md`。ページの入口 → `web/page.ts` (Y-12)。サーバーの共通の所 → `system.md`。

## ② 用語の表

| 言葉 | 意味 |
|---|---|
| クラフトボックス | 投稿された完成品の箱。オーナーの精査待ちの列 |
| お題 | 精査を通った物。ベース・アイテムレベル・狙い (段の下限つき)・創生の樹の印 |
| 挑戦 | スタートを押してから 1 時間の 1 回分。サーバーが始めた時刻を持つ |
| 提出 | 挑戦の中で 100 人回した結果と木を送る事 |
| 解決 | 提出の完成率が 90% 以上 |
| 費用 (点) | 100 人回しの `perItem` = 全員の合計 ÷ 完成数 (失敗の分も入る)。神で出す |

## ③ 決まり

### A. 大枠 (10-22 の決めのまま。ここは聞かない)

- **D-01 1 日 1 個**: 精査を通った物を古い順に 1 日 1 個、毎朝 7:00 (JST) に出す。未解決は溜まり、月曜 7:00 に全部消える。 — オーナー 10-22
- **D-02 競うのは平均の費用**: シミュで木を組み、100 人回しの費用 (②) が安いほど上。完成率 90% 以上で解決。 — オーナー 10-22・10-31 (順位の形)
- **D-03 ベース固定・フラクチャースタート**: ベースとアイテムレベルはお題のまま。始まりは狙いから 1 つ選んだフラクチャー済みのレアで、ここまでの費用は数えない (S-13 の (a) だけ)。 — オーナー 10-22
- **D-04 段を緩めるのは精査で**: 投稿の段のままでなく、お題ごとに「T○ 以上」へ緩める。創生の樹の MOD はお題に 1 つまで。 — オーナー 10-22

### B. 導線 (入口 2 つ・投稿の口 3 つ)

```
[タブ「デイリー」] ─→ 一覧 ?page=daily ─→ お題 ?page=daily&q=<id> ─→ スタート ─→ 挑戦 ?page=daily-play&q=<id>
                         │
                         └ お題を投稿 ─→ 投稿 ?page=daily-post ─┬ ① エミュのアイテムを使う
[エミュ「デイリーに投稿」] ─────────────────→ (確かめへ直行)      ├ ② poe.ninja のコピーを貼る
                                                               └ ③ トレードのコピーを貼る
                                               ↓
                                    確かめ (カード・読めなかった行) → 投稿 → クラフトボックス → 精査 → 順番待ち
```

- **D-10 入口は 2 つ**: 上のタブ「デイリー」(今の ModeTabs) と、エミュの設定の欄 (M-05) の「デイリーに投稿 →」(「シミュレーターへ →」の隣)。エミュのボタンは MOD が 1 つ以上ある時だけ押せる。 — オーナー 11-01「デイリークラフトタブからもエミュからもいけるようにしたいね」
- **D-11 投稿のページは 1 枚**: 上に ① エミュ、下に ②③ の貼る欄。貼る欄は 1 つで、poe.ninja・トレード・ゲームの Ctrl+C を同じ `parseItemText` で読む (S-08 と同じ読み。口を分けても中身は同じなので見出しに 2 つの名前を並べるだけ)。
- **D-12 ① エミュの口**: エミュに MOD のあるアイテムがあればそのカードと「これを使う」。無ければ「エミュで作る →」でエミュへ移り、D-10 のボタンで戻る。エミュの作りかけは消さない。タブからでもエミュからでも、同じ確かめの画面に着く。
- **D-13 確かめの画面**: 完成形のカード (StageItemCard)・読めなかった行・弾いた訳・ニックネームと一言 (任意) を見て「投稿する」。読み方が 2 通りある時は S-08 の「仮の読み」と同じ候補を出す。
- **D-14 弾く物 (エンジンで判定)**: ベースが読めない・狙いが 0・未発現の行がある・ユニーク・創生の樹の MOD が 2 つ以上・`goalBlock` が断る物。弾いた時は行に訳を出し、直せる物は直して投稿できる。付かない組み合わせはここで止まるので精査へ来ない (オーナー 10-22 の見込みどおり)。
- **D-15 投稿の後**: 「精査の後に出ます」の一言と一覧へのボタン。自分の投稿の状態 (待ち・出た) はこのブラウザに覚えて一覧の下に出す。

### C. 精査

- **D-20 精査はオーナーの手元で**: 画面は作らない。投稿は D1 に溜まり、手元の台本 (`wrangler d1`、Y-91) が一覧を出し、オーナーが OK・段の下限・表示名を決める。AI の係が下読みする形は後で足せる。 — オーナー 10-22「一旦オーナーの所に来て精査」「たぶん専用のエージェント」
- **D-21 お題を出す時に固定する物**: 狙いと段の下限・相場の写し・種 (D-34)・エンジンの版。お題の出ている間は変えない。

### D. 挑戦 (シミュの木 + 時間制限)

- **D-30 木はシミュそのもの**: 箱・手の窓・棚・MOD 一覧の窓・穴チェック・100 人回す・1 つ戻す・線と並べ方・見本はシミュの部品とエンジンをそのまま使う。デイリーの中だけの判定・確率を足さない (G-06・S-110)。MOD 一覧も今のシミュの物。 — オーナー 11-01「チャレンジ場所は勿論シミュでMOD一覧ページも勿論シミュの奴」
- **D-31 違うのは帯と皮だけ**: 下の表 (D-40) の外すものを外し、上の帯をデイリーの物にし、見た目を D-60 にする。 — オーナー 11-01「要はシミュレーターなんだけどUIが違うシミュレーターかな」
- **D-32 時間制限**: スタートを押した時刻をサーバーが持ち、そこから 1 時間。残りは帯の真ん中に大きく。止める・延ばすは無し。残り 10 分と 1 分で色が変わる。 — オーナー 11-01「スタートボタンから1時間以内作成とかのが燃えるかなって」
- **D-33 流れ**: スタート → (時間が始まる) → フラクチャーを選ぶ (今の DailyStart) → 木 → 穴チェック → 100 人回す → 提出。途中でタブを閉じても時間は進み、開き直すと木は戻る (このブラウザに覚える)。
- **D-34 同じ条件で比べる**: 回す種・値段はお題に固定 (D-21)。値段の手入力・ベースの値段は無い。回す人数は 100 (S-70 の RUN_N)。
- **D-35 提出できる条件**: 穴チェック合格 + 100 人回した直後の結果がある。完成率 90% 未満でも提出はできるが「未解決」の記録で順位に載らない。
- **D-36 別の場所の木を持ち込まない**: 挑戦の中はレシピの読み込み・貼り付け・共有 URL を受けない。

### E. 順位

- **D-50 順位**: お題ごとに、解決した提出を費用の安い順。同じ費用なら先に出した人。出す列 = 順位・ニックネーム・費用・完成率・使った時間。手・木は見せない (10-22「手の公開は別の機会」)。
- **D-51 ニックネーム**: ログイン無し。このブラウザに覚える。12 字まで、URL は不可。

### F. サーバー

- **D-55 表 (D1、server/live、次の番号 0014)**:

| 表 | 列 |
|---|---|
| `daily_box` (投稿) | id・created・ip_hash・nick・note・item (JSON: ベース・アイテムレベル・MOD)・status (wait / ok / no) |
| `daily_topics` (お題) | id・box_id・day (出た日)・week・base・ilvl・aims (JSON: 段の下限つき)・prices (JSON: 写し)・seed・engine_ver・shown_by |
| `daily_tries` (挑戦) | topic_id・uid・nick・started_at・submitted_at・cost・rate・recipe (exiledesk-recipe/1)・checked (検算)・PK (topic_id, uid) |

- **D-56 口**: `GET /daily.json` (今週のお題と順位の上位、端のキャッシュ 60 秒、デイリーのページを開いた時だけ) / `POST /daily/box` (投稿) / `POST /daily/start` / `POST /daily/submit`。誰でも書ける口は Y-94 (IP ごとの数・大きさの上限・bot よけ)。投稿は同じ IP から 1 時間 5 件・item 4KB まで、recipe 32KB まで。提出は締め切り + 30 秒まで受ける。
- **D-57 Y-100 の例外**: スタートと提出と投稿は「押した時の 1 回」なので、Y-100 の例外に足す (打つ・回す間は 0 のまま)。普段の枠の 1 割以下 (Y-73) に収まるかはサーバー管理人が見る。
- **D-58 回し直しはサーバーでしない**: Workers の無料の枠は 1 回の CPU が 10ms なので 100 人回しはできず、有料にもしない (Y-76)。費用は端末が出した数字を受け、順位の上位だけ手元の朝の台本 (Y-45 と同じ形) が同じ種・同じ値段で回し直し、合わない物を外す。本物の値を見るのは順位の上位だけ。
- **D-59 朝の切り替え**: live の cron に 7:00 JST (`0 22 * * *`) を足し、1 件出す。月曜は同じ cron で未解決を畳む。cron の本数の上限はサーバー管理人が確かめる。

## ④ 表示の決まり

- **D-60 見た目は皮だけ替える**: 色はページの一番外の印 (`data-daily-skin`) の下で `--exile-*` のトークンを上書きする (U-46。hex は style.css だけなのでデザイン部長へ)。部品の形・枠の絵 (U-41) は同じ物を暗くして使う。案は 3 通りを別に出す。 — オーナー 11-01「今のシミュよりももっとダークな感じのUI」
- **D-61 広告**: 一覧・お題・投稿のページは文章のページで両脇の枠 (Y-20)。挑戦のページは操作の画面なので枠なし (WebApp の `textPage` から外す、デザイン部長へ)。
- **D-62 日英**: U-60〜62。用語集に「クラフトボックス」が無いので足す (英語はオーナーに聞く)。
- **D-63 スイッチ**: 全部 `daily` の下。別のスイッチを増やさない。

### スマホ

- **D-70 組むのは幅 768 以上** (S-94g と同じ境、`useViewOnlyWidth`)。それより狭い時は スタートを出さず「挑戦は PC で」の 1 行。一覧・お題・順位は読める、投稿は貼る欄だけ使える (エミュの口はスマホのエミュから)。 — ブラックの読み 11-01、聞く事 Q8

## ⑤ 不変条件

- デイリーの木と同じ手順をシミュで回すと同じ種・値段で同じ費用になる (D-30)。見張りを足す時はこれを 1 本。
- 締め切り + 30 秒の後の提出は順位に載らない (D-32・D-56)。
- 挑戦の間、スタート・提出の外に Worker への取り物が増えない (D-57)。

## ⑥ 新しい物を足す手順

1. この紙に D-xx を書く → オーナーの OK (G-20)。木の決まりなら `sim-tree.md` へ (D-30)。
2. `daily` のスイッチの下で作る。よその部の物はブラック経由。
3. 同じ commit でこの紙の状態を直す。
