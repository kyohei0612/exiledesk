## 1. 大本 (全部の設計図より上)

- **G-01 ゲームどおり**: 結果 (付き方・確率・固定・打てるか) はゲームの挙動どおり。何をゲームの正とするか (出どころの順 = poe2db が正・トレードは確かめ・その次が CoE とオーナーのゲーム、クライアントは根拠にしない) は E-01〜04。
- **G-02 書いてある効果どおり**: カレンシー・お告げはゲームの説明文に書いてある効果で動く。乱数に関係ない条件以外の上限・制限を足さない。
- **G-03 違うのは狙いの指定だけ (シミュ)**: 打つ手はゲームどおり自由。ゲームと違うのは ☑ で狙いの MOD を指定できる所だけで、☑ の無い物は外れ。
- **G-04 日本語と挙動が合う**: 画面の文・名前・札は、実際に起きる動きと必ず合う。合わない物はバグ。
- **G-05 名前はエンジン参照**: カレンシー・お告げ・エッセンス・骨・MOD の名前は、エンジン / データの名前の関数から取る。画面で直書きしない。英語も同じ (poe2db の英語)。
- **G-06 エンジンが正、画面は呼ぶだけ**: 打つ・読む・比べる・MOD の文や値を作る中身はエンジン (ジン) が持ち、画面は関数を呼ぶ。同じ判定を 2 か所に書かない (1 か所直せば全部の画面が直る)。
- **G-07 Web だけ**: 当分は Web だけを更新。アプリは触らない。
- **G-08 UI はオーナーの OK の後**: 見た目・操作の変更はスイッチ (`src/web/release-flags.ts`) の下で作り、オーナーが触って OK の後に本番 (触るのはブラックの「確認して」の時に dev 1440 で、R-13)。データ・決まりの直しはすぐ出してよい。英語はセットで。書き方は U-70〜73、開け方と出し方は R-02・R-05。

## 3. 書き方の型

- **1 つの決まりは 1 枚にだけ書く**。ほかの紙・メモ・部の README・コードのコメントは番号で指すだけ (例: 「名前は G-05」「同じ形は S-10」)。中身を写さない。
- 決まり 1 つ = 番号・一文の決まり・状態・出どころ (オーナーの言葉と日付 / poe2db など)・確かめ方 (見張り / 外の正解 / 画面)。
- 状態は次の 5 つのどれか。撤回した物は消さずに残す。
  - `有効`: 本番がこの決まりどおり (スイッチが RELEASED に入った物・スイッチの無い物)。
  - `オーナー OK 済み・本番待ち (スイッチ <名前>)`: オーナーが OK したが、まだ本番に出ていない。スイッチの無い直しは「スイッチなし、次の deploy:web で出る」と書く。出たら `有効` に直す。
  - `仮 (オーナーの OK 待ち)`: 作った・書いたが、オーナーがまだ見ていない / 決めていない。
  - `未決`: 決まっていない。中身は ⑦ に書く。
  - `撤回 (日付・理由、置き換えた番号)`。
- 決まりの一部だけ本番待ちの時は、状態の行に「有効 (〜は オーナー OK 済み・本番待ち (スイッチ X))」と分けて書く。
- ⑦ には本当に残っている物 (未決・オーナーの選び待ち・決めたが作りの残り) だけを置く。片付いた物は本文へ移して ⑦ から消す。番号はほかの紙・todo が指しているので付け替えない (抜けた番号はそのまま)。
- 各紙の章立て: ① この紙の範囲 ② 状態・用語の表 ③ 決まり (番号付き) ④ 表示の決まり ⑤ 不変条件 (どんな時も成り立つ事 = 見張りが確かめる) ⑥ 新しい物を足す手順 ⑦ 残っている仮・未決。

## 4. 進め方

- **G-20 新しい事は先に設計図**: 設計図に書く → オーナーの OK (UI・仕様の決め) → 作る → 同じ commit で設計図を直す。直しだけの時も、決まりが変わるなら同じ commit で紙を直す。
- **G-21 足したらフルチェック**: 新しい手・状態・画面を足したら、出す前に見張り (`scripts/sim-watch` ほか) を 1 回回す。見張りは dev 1440 で回し (シミュは合格レシピ 3 本 + 見本の木を 30 人、エミュは 30 手)、本番の作り (1460 / 1461、1 回 5 分) は出す直前の 1 回だけで同時に 1 つまで、本番との照らしは出す中身に関係するページだけ (R-09・R-15)。モンキーはオーナーの指示の時だけ (足した所を中心に)。回し方と、モンキーを立てる時 (オーナーの指示の時だけ) は R-15〜18。フルチェック (見張りを全部) は大きな変更の後と出す前だけ、1 か所の直しはスナップだけ。見張りは時間で待たず画面の変化で次へ進み (秒数は止まったと見る上限だけ)、回し直しはオーナーに聞く (ブラック経由で「何のために・どれを・何分」)。出どころ オーナー 10-29「普通に変わったら次へでええやろ時間で待つのやばいわ」「1回しもっかい回すかは俺に聞いてくれ無駄に回すことないから」、10-29 夜 確かめの削り方 (「おｋそれで」)。
- **G-22 合格の基準**: 合格と言えるのは、外の正解 (トレード・poe2db・CoE・オーナーのゲーム)・見張りの不変条件・オーナーの目のどれかだけ。自分で作ったテストが通っただけでは合格にしない。確かめは書いた本人と別のセッション (最終チェック長・モンキー)。
- **G-23 頼む文の型**: 目的・オーナーの言葉 (引用)・ブラックの読み・触ってよいファイル・返す形・関係する番号・終わりの条件。番号はその頼みに要る物だけ (設計図を全部読ませない)、確かめを頼む時は回す先 (dev 1440 か本番の作り)・回数・人数 / 手数も書き、返すのは終わった時だけ (「〜を待っています」の途中の知らせを出させない。出どころ 10-29 夜 確かめの削り方、オーナー「おｋそれで」)。訂正は「今の作業を止めて」と頭に書き、止まってから次を送る。
- **G-24 大きな決め (構造・置き場) だけ ADR**: `docs/decisions/`。設計図はその上の日々の決まり。
- **G-25 オーナーの指示の言葉** (10-28): 頭の一言で扱いを分ける。「決め:」= 設計図に書く決まり、「案:」「どう思う？」= 決めずに意見を返す、「バグ:」= 直すだけ (決まりは変えない)、「訂正:」= 動いている作業を止めてから直す。バグは「何をしたら・どうなって・本当はどうなるはず」と絵。大きい新しい事は、作る前にブラックが「設計図にこう書く」を返して OK をもらう (小さい直しは聞かずに進める)。ブラックの質問は番号付き、答えも番号で。合図の言葉: 「出して」= 本番へ、「任せる」= 大本で決めて進め、後で一覧で見せる。(「固定版」= 1461 を立て直す合図は 10-28 夜に撤回、オーナーの確かめはブラックの「確認して」で dev 1440 = R-13。) 頭の一言が無い時は、ブラックが「決め / 案 / バグ」のどれと読んだかを返事に書く。
