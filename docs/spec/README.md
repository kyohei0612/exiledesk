# 設計図 (全体) — ExileDesk の決まりの正

ここが ExileDesk の「決まり」の正の置き場。2026-10-28 オーナー「大前提、全体及び各項目の設計図がいる」で作った。
地図 (どこに何があるか) は `docs/ARCHITECTURE.md`、組織 (誰が何を持つか) は `docs/org/README.md`。この設計図は「どう動くべきか」を持つ。

## 1. 大本 (全部の設計図より上)

- **G-01 ゲームどおり**: 結果 (付き方・確率・固定・打てるか) はゲームの挙動どおり。出どころの順は poe2db > トレード (取引所のデータ、確かめ) > Craft of Exile・オーナーのゲームでの確認 (10-28 オーナー「全体の順でおｋ」)。クライアントは根拠にしない。
- **G-02 書いてある効果どおり**: カレンシー・お告げはゲームの説明文に書いてある効果で動く。乱数に関係ない条件以外の上限・制限を足さない。
- **G-03 違うのは狙いの指定だけ (シミュ)**: 打つ手はゲームどおり自由。ゲームと違うのは ☑ で狙いの MOD を指定できる所だけで、☑ の無い物は外れ。
- **G-04 日本語と挙動が合う**: 画面の文・名前・札は、実際に起きる動きと必ず合う。合わない物はバグ。
- **G-05 名前はエンジン参照**: カレンシー・お告げ・エッセンス・骨・MOD の名前は、エンジン / データの名前の関数から取る。画面で直書きしない。英語も同じ (poe2db の英語)。
- **G-06 エンジンが正、画面は呼ぶだけ**: 打つ・読む・比べる・MOD の文や値を作る中身はエンジン (ジン) が持ち、画面は関数を呼ぶ。同じ判定を 2 か所に書かない (1 か所直せば全部の画面が直る)。
- **G-07 Web だけ**: 当分は Web だけを更新。アプリは触らない。
- **G-08 UI はオーナーの OK の後**: 見た目・操作の変更はスイッチ (`src/web/release-flags.ts`) の下で作り、オーナーが固定の版 (1461) で触って OK の後に本番。データ・決まりの直しはすぐ出してよい。英語はセットで。

## 3. 書き方の型

- **1 つの決まりは 1 枚にだけ書く**。ほかの紙・メモ・部の README・コードのコメントは番号で指すだけ (例: 「名前は G-05」「同じ形は S-10」)。中身を写さない。
- 決まり 1 つ = 番号・一文の決まり・状態・出どころ (オーナーの言葉と日付 / poe2db など)・確かめ方 (見張り / 外の正解 / 画面)。
- 状態は `有効` / `仮 (オーナー確認待ち)` / `撤回 (日付・理由、置き換えた番号)`。撤回した物は消さずに残す。
- 各紙の章立て: ① この紙の範囲 ② 状態・用語の表 ③ 決まり (番号付き) ④ 表示の決まり ⑤ 不変条件 (どんな時も成り立つ事 = 見張りが確かめる) ⑥ 新しい物を足す手順 ⑦ 残っている仮・未決。

## 4. 進め方

- **G-20 新しい事は先に設計図**: 設計図に書く → オーナーの OK (UI・仕様の決め) → 作る → 同じ commit で設計図を直す。直しだけの時も、決まりが変わるなら同じ commit で紙を直す。
- **G-21 足したらフルチェック**: 新しい手・状態・画面を足したら、出す前に見張り (`scripts/sim-watch` ほか) を全部の見本で回し、足した所を中心にモンキー。
- **G-22 合格の基準**: 合格と言えるのは、外の正解 (トレード・poe2db・CoE・オーナーのゲーム)・見張りの不変条件・オーナーの目のどれかだけ。自分で作ったテストが通っただけでは合格にしない。確かめは書いた本人と別のセッション (最終チェック長・モンキー)。
- **G-23 頼む文の型**: 目的・オーナーの言葉 (引用)・ブラックの読み・触ってよいファイル・返す形・関係する番号・終わりの条件。訂正は「今の作業を止めて」と頭に書き、止まってから次を送る。
- **G-25 オーナーの指示の言葉** (10-28): 頭の一言で扱いを分ける。「決め:」= 設計図に書く決まり、「案:」「どう思う？」= 決めずに意見を返す、「バグ:」= 直すだけ (決まりは変えない)、「訂正:」= 動いている作業を止めてから直す。バグは「何をしたら・どうなって・本当はどうなるはず」と絵。大きい新しい事は、作る前にブラックが「設計図にこう書く」を返して OK をもらう (小さい直しは聞かずに進める)。ブラックの質問は番号付き、答えも番号で。合図の言葉: 「固定版」= 1461 を立て直して触れるように、「出して」= 本番へ、「任せる」= 大本で決めて進め、後で一覧で見せる。頭の一言が無い時は、ブラックが「決め / 案 / バグ」のどれと読んだかを返事に書く。
- **G-24 大きな決め (構造・置き場) だけ ADR**: `docs/decisions/`。設計図はその上の日々の決まり。

## 5. 片付け

設計図ができた部から、古い情報を片付ける: docs/org/<部>/README.md の決まりは番号を指す形にする、notes/ の決めは設計図へ写して notes は記録として残す、メモは番号を指す 1 行にする、置き換えた ADR は状態を「置き換え済み」にする、コードの古い説明は番号を指す形に直す。
