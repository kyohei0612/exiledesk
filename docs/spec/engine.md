## ② 状態・用語の表

| 用語 | 意味 | コードの名前 |
|---|---|---|
| 側 | プレフィックス / サフィックス | `StageSide` (`prefix` / `suffix`) |
| 枠の上限 | レアリティの上限 + 暗黙の ±N (ジュエル・エッセンスの +1 枠など) | `limitOf` (stage-core.ts) |
| 上限超え | レアで、ある側の MOD が上限より多い状態 | `overLimit` |
| 行 | MOD の置き場の単位 (`Gloves_str`・`Wands_fire` など) | `classOfBase` (htc/bridge.ts) |
| 段 | 同じ MOD の強さの段 (T1 が一番上)。画面の言葉は「ティア」(U-62) | `tierIndex` |
| 系統 | 同時に 1 つしか付かない MOD のまとまり | `family` (直接比べない、E-11) |
| 一般 MOD / 冒涜専用 MOD / クラフト MOD | MOD の出どころ (言い方は E-95) | source `normal` / `desecrated` / `essence`・`perfect_essence` |
| 未発現 | 骨で付いた、まだ中身の決まっていない冒涜の枠 | `m.unrevealed` |
| 発現済みの冒涜 | 発現で決まった冒涜の MOD (一般 MOD のこともある) | `m.desecrated && !m.unrevealed` |
| 固定 (フラクチャー) | フラクチャーで固定した MOD。消す・振り直すの対象にならない | `m.fractured` |
| 印 | アビサルロードの紋章 (深淵のエッセンスで付く) | `noAbyssMark` ほか |
| 聖別済み | 聖別のお告げで神を打った後の品 | `SANCTIFIED_REASON` |
| 不成立 | 打ったが決まりで弾かれた。カレンシーは減らない | `skip` / `skipRandom` |
| 説明文の分解 | カレンシー = 対象・動作・制約・出どころのデータ (ADR-004) | `CurrencySpec` / `OmenSpec` (spec/types.ts) |

## ③ 決まり

書き方: **番号 決まり** — 状態 / 出どころ / 確かめ方。

### データの出どころ

- **E-01 出どころの正は poe2db。トレード (取引所のデータ) は確かめに使う。その次が Craft of Exile・オーナーのゲームでの確認。** 付く・付かない・段・ベースの有無は poe2db に合わせ、トレードのデータ (`services/items/tradeable-bases.json`・`i18n/trade2-*.json`、消さない) は照らすだけ。食い違ってもトレードに合わせて直さない (例: タリスマンの物理の段はトレードが P6、poe2db とデータは 9 段で T5 → データのまま)。クライアントは根拠にしない (今ある JSON の出どころの記録だけ、ARCHITECTURE の「データの出どころ」)。PoB は使わない。 — 有効 (10-28 オーナーの決め、コードの変更なし) / G-01、オーナー 10-09・10-17「db 見ときゃいい」・10-28「やっぱりdbにしようかトレードは確認くらいでおk」・同日「全体の順でおｋ」(タリスマンだけでなく全体、10-23「トレードは 1 番信頼できる」の順は 10-28 で置き換え) / 外の正解: `scripts/audit-poe2db-mods.mjs`・`audit-poe2db-tags.mjs` が 0
- **E-02 写しどうしが食い違って決まらない値は poe2db に合わせる。聞かない。** (例: 兜の憤怒 45 段目の秒) — 有効 / オーナー 10-20・10-23 / 外の正解: poe2db の部位のページ
- **E-03 公開値の無い重み・割合は Craft of Exile (beta) のデータと動きを正にする。** ルーンの特殊 MOD は CoE (Krakenbul の実測) → `htc/rune-weights.json`。冒涜専用 MOD どうしの重みは全部同じ。出どころの当て先はメモ craft-weight-sources。 — 有効 / ADR-004 の 4、v0.1.528 / 外の正解: `data-cache/coe-beta-data.json`・`scripts/check-htc-odds-vs-coe`
- **E-04 こちらで決めた値には出どころと日付を付ける。** spec の `source` (client / poe2db / coe / owner / community / assumed) に書く。 — 有効 / ADR-004 / 確かめ: spec を読む

### MOD の置き場・重み・段

- **E-10 MOD の置き場・重み・段・文はエンジンの行 1 か所から取る。** 読み込みは `services/htc/patch.ts` の `loadHtcPatch()` (同梱 + `extra-bases.json` + `weight-overrides.ts` + `poe2db-pool-fixes.json`)、ベース名 → 行は `bridge.ts` の `classOfBase`、MOD を並べるのは `craft-stage/mod-list.ts` の `modListFor`。自前の表を作らない。 — 有効 / オーナー 09-29・10-05 / 見張り: `check-engine-entry` E (画面の中の .tiers・生の JSON)
- **E-11 系統・重み・出やすさは `services/mods/mod-rules.ts`。** `m.family` を直接比べない。段の重みは `vendor/poe2htc/engine/pool.ts` の `modTierWeights` 1 本で、自分で足さない。 — 有効 / ARCHITECTURE / 見張り: `check-engine-entry` E
- **E-12 部位のまとまりは `services/mods/item-classes.ts` から引く** (`inGroup`・`inAny`・`kindOf`・`categoriesIn`・`canFracture`)。部位の名前を手で並べない。カレンシーの使い先は説明文の言葉 (武器・マーシャル武器・ワンド / スタッフ / セプター・防具・宝飾品・指輪かアミュレット・矢筒・ジュエル)。表は poe2db と食い違ったら poe2db に合わせる。 — 有効 / 10-13 総点検 (`docs/archive/2026-10-13-item-class-audit.md`)・10-17 / 見張り: `tests/item-classes.test.ts`
- **E-13 暗黙が足すタグも置き場に入る。** 例: グラスピングメイルは鎧 (Body Armours、筋力・器用さ・知性の混合 = タグ `str_dex_int_armour`、要求 41 / 41 / 41、レベル 65) だが暗黙の adds_tags = ring で指輪の MOD が付き、カタリストも使える (専用の行 `Body_Armours_ring_str_dex_int`)。暗黙が一緒に足す `genesis_tree_caster`・`genesis_tree_minion` は創生の樹 (落ちる物だけ、`htcDropOnly`) の MOD 用で、クラフトの置き場には足さない。「この部位に◯◯は付かない」と言う前に暗黙を見る。ベースの選び画面の札は E-98。 — 有効 (10-28 オーナーの決め、エンジンの変更なし) / 要望 a286ced8・poe2db (10-28 に読み直し)「Can roll Ring Modifiers」「Catalysts can be applied to this item」 / 外の正解: CoE beta の Grasping Mail の表、`tests/grasping-mail.test.ts`
- **E-14 MOD の値に固定値は無い。** +1 も stat の値で、品質・ソケットの効果・お告げなどで動く前提で持つ (`stage-runes.json` の effects.stats など)。丸めが分からない時はデータか実測で。 — 有効 / オーナー 10-10「固定値のものなんてのは存在しない」 / 外の正解: 実物 (セールの凱旋 +2)
- **E-15 暗黙にもタグがあり、カタリストの品質で伸びる。** タグ・品質・上の数値を触る時は暗黙 (`implicitRows`・`htc/implicit-stats.json`) も見る。 — 有効 / オーナー 10-12 / 確かめ: 暗黙の値の表示
- **E-16 MOD のタグと冒涜の陣営は poe2db に合わせる** (`htc/poe2db-tag-fixes.json`)。poe2db を取り直したら照合を回す。 — 有効 / 10-18 v0.1.572、`docs/reviews/2026-10-18-tag-audit.md` / 外の正解: `audit-poe2db-tags.mjs` が 0
- **E-17 エッセンスで付けた系統は、後から骨・高貴・カオスで同じ系統を付けさせない。** (`takenCraftedFamilies`) — 有効 / メモ poe2-craft-rules-confirmed / 見張り: golden
- **E-18 フラスコ・チャームはエンジンに足さない。** (貼り付けでは「未対応」) — 有効 / オーナー 10-20
- **E-19 コラプトで付く・変わる MOD と値の幅はエンジンが 1 か所に持つ** (`services/mods/corruption.ts` + `corruption-mods.json` ← `scripts/build-corruption-mods.mjs`、poe2db から)。 — 有効 / オーナー 10-20

### カレンシーの動き (全般)

- **E-20 カレンシーとお告げは説明文の分解で動かす。** 対象・動作の部品 (`setRarity`・`add`・`remove`・`addUnrevealed`・`reroll`・`fracture`・`quality`・`socket`/`augment` ほか)・制約で書き、お告げは `OmenEffect` (部品への修飾) で書く。カレンシー固有の処理・部位の例外を書き足さない。 — 有効 / ADR-004 (2026-10-14) / 見張り: `tests/currency-spec-golden.test.ts`
- **E-21 打てるかは乱数に関係ない条件だけで決める。** 部位・レアリティ・コラプト・空き枠・お告げの前提など。試し打ちして棚から隠さない。こちらで上限・下限を足さない (ゲームの文にある上限だけ)。打てるかの判定は `spec/judge.ts` (画面は `useReason`)。 — 有効 / G-02、オーナー 10-12・10-20 / 見張り: golden、`tests/item-classes.test.ts`
- **E-22 説明文に書いてある効果はそのまま発動、書いていない所はランダム (候補から等しく)。** — 有効 / オーナー 10-16「普通なんも書いてなかったらそのまま効果発動、書いてないやつはランダム」 / 外の正解: CoE
- **E-23 決まりで弾かれたら不成立。カレンシーは減らず、ゲームと同じ文で理由を出し、工程に「弾かれた」と残す。** — 有効 / メモ feedback-game-rules-as-written / 確かめ: エミュの画面
- **E-24 マジックはプレ 1・サフィ 1。レアの枠は `limitOf` (暗黙の ±N を含む)。** 決め打ちしない。ジュエルのレアはプレ 2・サフィ 2 (`jewel-bases.json` の limits)。 — 有効 (ジュエルは 10-28 に確かめ、コードの変更なし) / メモ poe2-craft-rules-confirmed、ADR-004 の背景 (不在のアミュレット)、ジュエルは CoE beta の部位の affixes 4 (poe2db のページには数の記載が無い、10-28) / 見張り: golden
- **E-25 上限を超えた側の MOD を消す手 (カオスなど) に当たったら手ごと不成立 (オーブも減らない)。** 反対の側に空きがあっても同じ。`remove` の制約として書く (`overLimitVoids`)。 — 有効 / オーナーがゲームで確認 10-14 / 確かめ: ジン 11 本目の調べ (10-26、直しなし)
- **E-26 聖別済みの品には何も打てない。** 品質・カタリスト・オーブ・お告げ・エッセンス・骨・ルーンの差し替え・品質 / アイテムレベルの欄も止める。通すのは聖別の数値の帯・鏡・抽出・解呪・サルベージだけ (`apply-currency.ts` の入口、`SANCTIFIED_REASON`)。 — 有効 / オーナーがゲームで確認 10-22 / 見張り: golden
- **E-27 お告げは打っても外さないのが既定。** 反対のお告げは掛け替え (`OMEN_EXCLUSIVE`)。 — 有効 / オーナー 10-18 / 見張り: held-odds-parity
- **E-28 ヴァールのオーブ・可能性のオーブは無い。足し直さない。** 残すのはヴァールのエンチャントの表と `applySanctify` (生贄・インフューザー・聖別のお告げが使う)。古い手順にあれば「まだ使えない」で飛ばす。 — 有効 / オーナー 10-13・10-16 / 確かめ: 棚に無い
- **E-29 棚に無い手 (ルーンを外す・解呪・サルベージ・宝飾職人・鑑定・ヴァール系の道具) は説明文の分解に移さない。** 古い手順の再生のためだけに残す。 — 有効 / ADR-004 の進み具合 10-17

### オーブ

- **E-30 カオス = 消す + 付ける (別々の部品)。** 消した後に空きがある側 (両側が候補) から重みで付ける。どこにも空きが無ければ付かない。消した MOD と同じ物 (同じ段) もまた付きうる。`replace` の部品は作らない。 — 有効 / ADR-004 の決め 2 (10-14)、リサーチ長が CoE で確認 10-26 / 外の正解: CoE
- **E-31 大いなる高貴のお告げで空きが 1 つなら 1 つだけ付く。** — 有効 / CoE rollAffixes / チェックリスト
- **E-32 触媒の高貴のお告げは品質の倍率 1 + 0.2 × 品質 (20% 超は +0.12 / %)。大いなる高貴と重ねると 2 つとも重くなる。** — 有効 / CoE exaltedParams、v0.1.525 / 外の正解: CoE
- **E-33 削減のお告げは一番低い MOD レベルを消す。並んだら等しく。未発現の枠は MOD レベル 1。** — 有効 / CoE poe2_chaos、poe2wiki 0.3.1 / 外の正解: CoE
- **E-34 神のオーブは固定以外・未発現以外の値を振り直す。暗黙の値も、ユニークも振り直す。** — 有効 / オーナー 10-08・10-12 / 見張り: golden
- **E-35 聖別は振り直してから 0.78〜1.22 倍。段の上限を超えることもある。** 値の計算の順は 素の値 → 聖別 → 品質 (取引所の実物で +6 が出る順)。 — 有効 / CoE (v0.1.547)、オーナー 10-17・10-21 / 外の正解: 取引所の実物
- **E-36 消去はノーマルに打てない。未発現の冒涜も普通の消去で消える。** — 有効 / CoE rarity_not_normal、オーナーがゲームで確認 10-08 / 見張り: golden

### フラクチャー

- **E-40 フラクチャーはレアで MOD 4 つ以上、固定は 1 つ。もう固定がある品・CanBeFractured でない部位には打てない。** (`modsAtLeast` 4・`noFractured`・`fracturableClass`) — 有効 / 説明文、オーナーがゲームで確認 10-08 / 見張り: golden
- **E-41 選ぶのは対象から等しく 1 つ。未発現の枠と冒涜で付いた MOD (冒涜専用でも一般 MOD でも) は選ばれない。クラフト・エッセンスの MOD は固定できる。** (`unfracturable`) — 有効 / オーナーが 24 回打って 0 回 (10-10)、CoE EmulatorManager.fracture (CoE は発現済みも選ぶので違う) / 外の正解: オーナーのゲーム
- **E-42 「MOD 4 つ以上」に未発現の枠も発現済みの冒涜も数える。固定は選べる MOD (E-41) から等しく。** 普通 3 + 冒涜 1 (未発現でも発現済みでも) なら打てて、固定は普通 3 つの中から 1/3 ずつ (`modsAtLeast` が `allMods` を見る、選ぶのは `unfracturable` を抜いた物)。 — 有効 (10-28 オーナーの決め、前からこの動きでコードの変更なし) / オーナー 10-28「打てる だから33％って話ただ冒涜にはフラクチャーかからないから発言しても未発現でもいっしょ」 / 見張り: `tests/desecrated-fracture.test.ts`、確かめ: 10-28 ジンの台本 (指輪の 3 通り × 6000 回で 0.331〜0.335、冒涜・未発現は 0 回、確率表 `fractureHit` も 0.333)

### エッセンス

- **E-50 無限のエッセンスは筋力・器用さ・知性のうち付いていない系統から等しく 1 つ。** — 有効 / オーナー、CoE poe2_essence
- **E-51 パーフェクトエッセンスは、付ける側が埋まっていれば必ずその側から 1 つ消してから付く。** (`remove` の `side` = エッセンスの MOD の側、埋まっている時だけ) — 有効 / オーナーがゲームで確認 10-14 / 見張り: golden
- **E-52 深淵のエッセンスは、未発現の冒涜があれば打てて印がそれと入れ替わる。発現済みの冒涜があると打てない。固定した印は置き換えない。** (`noRevealedDesecrated`・`unrevealedFirst`) — 有効 / オーナーがゲームで確認 10-16 夜 (v0.1.532)・10-17 / 見張り: golden

- **E-54 エッセンスの MOD は同じ系統の一般 MOD と一緒に付く。** — 有効 / メモ poe2-craft-rules-confirmed

### 骨・冒涜・発現

- **E-60 冒涜の MOD は 1 つまで。冒涜の MOD (未発現・発現済み) がある品には骨は打てない (置き換わらない)。** 先に消去などで消す。 (`oneDesecratedMod`) — 有効 / 説明文、オーナー 10-24「消さんと入れ替わらんやろ」 / 見張り: golden
- **E-61 骨の側: 両側が空いていれば半々。満杯なら固定以外から等しく 1 つ消して、消した側に付く。** マジックは側 1 つずつ。 — 有効 / CoE poe2_desecrate (10-16)、poe2wiki「If it removes a Prefix, it will add a Prefix」 / 外の正解: CoE
- **E-62 発現の候補は 3 つ。冒涜専用 MOD の個数は 1 / 2 / 3 個 = 85 / 14 / 1 %、冒涜専用どうしの重みは全部同じ、同じ系統は 2 つ出ない。** 残りは一般 MOD から重みで (同じ系統は抜く)。ルーンの MOD はルーンを差していれば候補に出る。候補を作るのは `drawOffers` 1 つ。出うる MOD と段 (重み > 0) の一覧は同じ置き場から `revealPool` (シミュの発現の窓の灰色、S-38、10-30)。 — 有効 / Reddit の指輪 563 回 (他の部位も指輪の比率、オーナー 10-10)、CoE getRevealPicks、オーナーがトレードで確認 10-20 / 見張り: held-odds-parity
- **E-63 冒涜専用 MOD はアイテムレベルを見ない。噛み切られた骨だけは見る (アイテムレベル 64 以下にだけ打てる、`GNAWED_MAX_ILVL`)。古代の骨はアイテムレベル 40 未満に打てない。** — 有効 / メモ poe2-craft-rules-confirmed、用語集 / 見張り: golden
- **E-64 骨の部位は item-classes から (`desecrationBoneFor`)。** セプターにも打てる (候補は一般 MOD だけ)。ジュエルは保存された頭蓋骨だけ。変質した鎖骨は装飾品だけ。 — 有効 / poe2wiki「Sceptres do not have exclusive desecrated…」、オーナー 10-11・10-14 / 見張り: `tests/item-classes.test.ts`
- **E-65 印から打つ骨の段の下限はアイテムレベル × 0.4 の切り捨て (`markFloorOf`)。** 印 (固定していない物) があれば必ず印を置き換える。 — 有効 / CoE poe2_desecrate、10-16 v0.1.531 / 外の正解: CoE
