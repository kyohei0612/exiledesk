## 背景

シミュレーションの手 (`PatternStep`) には、外れた時の決め方が積み重なっていた。

| 決め方 | 足した日 |
|---|---|
| onMiss (そのまま次へ / 外してもう一度 / 最初から …) と miss (外す物) | 10/6 |
| otherGone / otherJunk (お告げ無しの消去で反対側が消えた・付いた時) | 10/7 |
| on (起こりうる状況ごとの反応) | 10/8 |
| policy (形ごとの次の手) と resetTo (1 MOD 残し消去) | 10/8〜10/9 |

どれも「外れた時に何をするか」を別の言葉で決めていて、組み合わせが分かりにくかった。
10/9 に「打って決める」(形ごとに、打って結果を選び、次の手を決める) を作り、オーナーが「これを極める」と決めた。

## 決定

### 1. 型: 手は 3 つだけ

```ts
interface PlayRecipe { v: 2; moves: PlayMove[] }
interface PlayMove {
  use: string;                 // 打つ物 (カレンシー + お告げ)
  aim: PlayAim | null;         // 狙い。無ければ打つだけ (打って 1 手進む)
  shapes?: Record<string, PlayDecision>;  // 形 (狙い h・狙い以外 j) ごとの次の手
}
interface PlayAim { mods: {modId, minTierIndex}[]; need: number; side: "prefix" | "suffix" }
type PlayDecision = { use: string } | { go: "next" } | { go: "start" } | { go: "move"; to: number; strip?: number };
```

- **狙い無し** の手は、打ったら次の手へ進む。外れは無い。
- **狙いあり** の手は、打った後の狙いの側の形を見る。狙いが揃えば次の手へ進む。揃っていなければ、その形で決めた次の手を使う。
- **need は合計** で持つ。前の手で同じ狙いから付いた分も入れる。トリフラなら、カオスの手は 1、偉大の手は 3。
- **形** は狙いの側の「狙いの数・狙い以外の数」。空きは枠から引けば分かる。キーは `shape-table.ts` の shapeKey。
- **次の手** は 4 つ。
  - 打つ物を打つ。打った結果はまた形で見る。
  - 次の手へ進む。
  - 新しいベースで最初から。
  - N 手目へ戻る。strip を付けると、先に固定以外を strip 個まで素の消去で減らす。1 MOD 残し消去は strip 1。
- 打った結果で来うる形を、全部決めるまでレシピは完成にしない。残りの数は `playLeft` で出す。

### 2. 計算

`compilePlay` で今のエンジンの手 (`CompiledStep`) に変換し、`runPattern` で回す。

- 形の次の手は policy になる。打つ物は act、次の手へは next、最初からは restart、N 手目へは goto、strip 付きは reset (keep) になる。
- 決めていない形に来たら、新しいベースで最初からにする。UI で全部決めさせるので、普通は来ない。

### 3. UI (これから)

画面は手打ちと同じにする。

- アイテムの札と、今使えるカレンシーの棚を出す。使えない物は既定で畳む。
- カレンシーを押したら「MOD を狙う？」を聞く。狙わなければ打つだけで、1 手進む。
- 狙うなら、狙う MOD (どれか 1 MOD など) を選ぶ。打った結果は運任せにせず、「どうなった？」から選ぶ。確率も出す。
- 新しい形に来たら「このパターンの時」をアイテムの上に出し、そこでカレンシーを選ぶ。前に決めた形は前の手を自動で打つ。
- 「パターン N / M 決めた」を出し、全部決めるまで次へ進めない。
- 決めた手は文で並べ、押すとその形に戻って変えられる。

### 4. 前の型との関係

- 前の型 (`PatternStep`) は今の保存データのために残す。新しいレシピは `v: 2` の PlayRecipe で保存する。
- 前の型から PlayRecipe への変換は、UI を作る時に足す。onMiss などは、形の次の手に置き換えられる物だけ移す。

## まだ決めていないこと

- 形を狙いの側だけで数えている。両側に狙いがある時や、冒涜の未発現・エッセンスの枠が絡む時は、形の要素を足す必要がある。
- 変成・増強・王者 (マジック) やエッセンスの結果は、今は高貴と同じ「1 つ付く」で数えている。レアリティが変わる手の形を別に持つか。
- 削減のお告げのように、どれが消えるかがアイテムの中身で決まる手の結果の出し方。
- 確率は付ける物の重みから出す目安で、同じ系統の除外は見ていない。
