## 1. 型

```ts
interface QuizRecipe {
  v: 3;
  base: string; itemLevel: number;
  start: { kind: "white"; price: number }                 // 白を買う
       | { kind: "bought"; mods: GoalRef[]; price: number } // 付いた状態 (固定済みなど) を買う
       | { kind: "item"; item: StageItem; price: number };  // エミュレーターの今のアイテムから
  goal: GoalSlot[];   // 完成の MOD (ベースの枠の数まで。指輪なら 6、ジュエルは 4 + 侮蔑の 1)
  rules: QuizRule[];  // 答えた「この場合はこう」
}
interface GoalSlot {
  id: "A" | "B" | ...;            // 画面と条件で使う札
  side: "prefix" | "suffix";
  mods: { modId: string; minTierIndex: number }[]; // どれか 1 つで良い (候補)
  kind: "normal" | "desecrated" | "fractured" | "essence" | "crafted";
}
interface QuizRule { when: Situation; do: QuizAction }
type QuizAction =
  | { use: string; omens: string[] }                        // カレンシー + お告げ (棚の物そのまま)
  | { reveal: { want: GoalSlot["id"][]; echoes: boolean } } // 発現: 3 つに want があれば取る、無ければ反響で引き直し、それでも無ければ 1 つ目 (後で光のお告げの手が拾う)
  | { restart: true };                                      // 次のベースを買って最初から
```

## 2. 状況 (条件) の表し方

状況は **完成の札から見たアイテムの形** だけで書く。MOD の文や数値は条件に入れない。

| 項目 | 値 |
|---|---|
| 札ごと (A〜F) | 付いている / 付いているが段が低い / 無い |
| 側ごと | 狙い以外の MOD の数 (固定以外)、空きの数 (侮蔑などで増えた枠も込み) |
| 冒涜 | 未発現がある / 発現済みで狙い / 発現済みで外れ |
| その他 | レアリティ、作った MOD (エッセンス・感情) の有無 |

- 1 つの状況 = 上の全項目の値。答えた時の形がそのまま条件になる (完全一致)
- 「ここは何でも」に広げられる (例: 「A が付いていれば、他は問わずこの手」)。決まった項目の多い条件が先に当たる。並び順で迷わせない
- 判定はどれも、打つ前に見える物だけ (書いてある効果どおり)。弾かれた手 (`random`) は数えず、同じ状況のままもう一度その手
- 当たり所に関係なく打てない手 (棚に無い手) を答えには選ばせない。回している途中で来たら「この手は打てない」で止めて知らせる

## 3. クイズの進め方 (UI)

シミュレーターの中を `.g-tab` 3 つにする (1 つの `.g-panel`)。

1. **完成形** — 札 A〜F に MOD と段を選ぶ。札ごとに 普通 / 冒涜 / 固定 / エッセンス / 作った を切り替え。始め方 (白 / 付いた状態を買う / エミュレーターから) と値段
2. **クイズ** — 裏で回して、まだ答えていない状況に来たら止める。アイテムの札と「この時は?」を出し、棚 (エミュレーターと同じ部品) からカレンシー + お告げ、または 発現の選び方 / 最初から を選ぶ。来た回数の多い状況から順に出す。答えた一覧は既定で畳み、押すとその状況に戻して変えられる (1 つ戻す・Ctrl+Z)
   - 「残り N」: 回して来た未回答の状況の数。0 になったら結果へ進める
3. **結果** — 完成の割合・1 個の平均費用・中央 / 80% / 90% (運の幅)・カレンシーごとの数。ベース・アイテムレベル・段・値段を変えて回し直し (レシピは同じ)

エミュレーター側: 「レシピで 1 手」「最後まで」。今のアイテムに当たる答えを出してから打つ (どの答えが当たったかを札に出す)。打ち方は applyCurrency そのものなので、シミュレーターと結果がずれない。

文は最低限、説明は畳む。言葉は全部 `tr()` で日本語 + 英語 (ゲームの言葉はクライアントの原文)。

## オーナーの返事 (2026-10-12)

- 答えの手は「はい / いいえ」ではなく、今のシミュレーターの選び方 (棚 + お告げ) で選ばせる
