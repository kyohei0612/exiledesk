# ADR-004: カレンシーは説明文の分解で動かす (例外を書かない作り)

- 日付: 2026-10-14
- 状態: 決定 (2026-10-14、コードは封印中。封印が解けたら作り始める)
- オーナー指示:
  - 「エグザイルデスクは決められたルールの中で動きを決めてるから応用が効かなくなる。特に骨がいい例。骨の動作をそのまま解釈したらセプターに使えるやろ。そういう幅が無いから狭い使い方しかできん」
  - 「付き方はクラフトエグザイルが正しいから、仕組みの確認は自分のとこ回すんじゃなくてクラフトエグザイルを回さんとね」
  - 「db との調べもせず手書きで決めたルールは全て db やトレードサイト等の情報にのっとって決めて。土台から」
- 関連: ADR-001 (クラフトステージ)、[部位の種別の総点検](../reviews/2026-10-13-item-class-audit.md)、[手書きの決まりの総点検](../reviews/2026-10-14-rule-audit.md)

## 背景

今のエミュレーターは、カレンシーごとの関数 (`apply-currency.ts`・`apply-desecrate.ts`・`apply-essence.ts` …) の中に、
「この部位なら」「このお告げなら」「この時は打てない」を一つずつ書き足して動いている。

この 2 日で出た不具合は、どれも「人が書いた例外」が原因だった。

| 不具合 | 原因の例外 |
|---|---|
| タリスマンに勢力のお告げが使えない | 骨の部位の表にタリスマンが無く、防具に落ちた |
| 不在のアミュレットに変成で MOD が付く | マジックの枠を 1 / 1 で決め打ち (暗黙の ±1 を見ていない) |
| セプターに骨が出ない (自分で入れた) | 「専用 MOD が無いなら出さない」をこちらで決めた |
| コロナのアミュレットにルーンをはめられない | 「宝飾品はソケット 0」をこちらで決めた |
| ジュエルに普通の触媒が使える | 「ジュエルも触媒で上がる」を、カレンシーの区別なしに決めた |

どれも、説明文を素直に読めば最初から正しく動いた物。例外は書くたびに「想定外の組み合わせ」で壊れる。
約 130 個の手書きの決まりのうち、根拠が無い物が約 40 個あった (総点検)。

## 決定

### 1. カレンシーは 3 つの部品で書く

カレンシー (とお告げ) は、関数ではなく**説明文を分解したデータ**で持つ。

```ts
interface CurrencySpec {
  key: string;                     // "desecrate_ancient" など
  text: { en: string; ja: string } // クライアントの説明文 (根拠。画面のヘルプにもそのまま出す)
  target: Target;                  // 何に使えるか
  actions: Action[];               // 何をするか (順に)
  limits: Limit[];                 // 打てない時 (説明文・用語集・ゲームの決まり)
  source: Source;                  // 出どころ (client / poe2db / poe2wiki / coe / owner-ingame + 日付)
}
```

**対象 (Target)** は説明文の言葉そのまま: レアリティ (Normal / Magic / Rare) と、部位のまとまり
(武器・マーシャル武器・ワンド / スタッフ / セプター・防具・宝飾品・指輪かアミュレット・矢筒・ジュエル)。
まとまりは `item-classes.ts` (クライアントの表) から引く。部位の名前は書かない。

**動作 (Action)** は少数の部品の組み合わせ。カレンシー固有の処理は書かない。

| 部品 | 意味 | 使う物の例 |
|---|---|---|
| `setRarity(r)` | レアリティを変える | 変成・王者・錬金 |
| `add(n, pool, side?, floor?)` | 置き場から n 個付ける (空きが無い分は付かない) | 変成・増強・高貴・錬金 |
| `remove(n, pick, side?)` | 固定以外から n 個消す (pick = 等しく / 一番低い MOD レベル / 冒涜だけ) | 消去・カオス・削りのお告げ・光のお告げ |
| `addUnrevealed(pool, side?)` | 未発現の冒涜 MOD を 1 つ足す (満杯なら同じ側を 1 つ消す) | 骨 |
| `reroll(what)` | 値を振り直す (MOD / 暗黙 / 全部) | 神・祝福のお告げ |
| `fracture()` | 1 つを固定する | フラクチャー |
| `quality(+n, type?)` | 品質を上げる / 種類を決める | 品質のカレンシー・触媒 |
| `socket(+n)` / `augment(rune)` | ソケット・はめる | アーティフィサー・ルーン |
| `corrupt(outcomes)` | コラプトの結果から 1 つ | ヴァール |

**制約 (Limit)** は説明文と用語集から: 「冒涜の MOD は 1 つまで」「クラフト MOD は 1 つまで」
「最低 MOD レベルのあるカレンシーはアイテムレベルがそれより低い品には使えない」など。

**お告げ**は「次の◯◯の動作をこう変える」として、同じ部品への修飾で書く。
例: 右の消去 = `remove` の `side: "suffix"`、削り = `remove` の `pick: "lowestLevel"`、
勢力のお告げ = `addUnrevealed` の発現の候補に「その勢力の MOD を保証」、大いなる高貴 = `add` の `n: 2`。

### 2. アイテムの性質はデータから

部位の種別・片手 / 両手・枠の数 (レアリティの上限 + 暗黙の ±N)・ソケット (規格外の数・「兜として得る」の暗黙)・
付く MOD の置き場 (普通・エッセンス・冒涜・異界) は、クライアントの表と暗黙の文から引く (`item-classes.ts`・`htcBaseInfo`)。

### 3. 例: 骨

```ts
{
  key: "desecrate_ancient",
  text: { en: "Desecrates a Rare Weapon or Quiver" },
  target: { rarity: ["rare"], groups: ["weapon", "quiver"] },
  actions: [{ addUnrevealed: { pool: "desecrated+normal", floor: 40 } }],
  limits: ["oneDesecratedMod", "itemLevelAtLeastFloor"],
  source: { client: "BaseItemTypes / CurrencyItems", poe2wiki: "2026-10-14" },
}
```

セプターは「武器」なので対象に入る。冒涜の置き場に専用 MOD が無いので、発現の候補は普通の MOD から出る。
**例外を 1 行も書かずに** poe2wiki の「Sceptres do not have exclusive desecrated prefixes or suffixes」と同じ動きになる。

### 4. 確率・付き方の正解は Craft of Exile

- 重み・割合など公開値が無い物は、Craft of Exile (beta) のデータと動きを正解にする。
- こちらで決めた値は `assumed.ts` の一か所にまとめ、出どころと日付を付ける。画面のヘルプにも「仮」と出す。

### 5. テストは外の正解で

- 期待値はこちらの決まりではなく、外の正解の写し (poe2db の下限・クライアントの区分表・Craft of Exile のデータ・オーナーのゲームでの確認) から作る。
- 写しは `tests/truth/` に置き、取った日付と出どころを書く。パッチで変わったら写しを取り直すと、ずれた所でテストが落ちる。
- 「全部位 × 全カレンシー」の打てる / 打てないは、説明文と区分表から作った期待値で総当たりにする。

## 進め方 (オーナーの OK の後)

1. **土台:** `CurrencySpec` の型と動作の部品、対象・制約の判定を作る。今の関数と同じ結果になるかを、今の手順の再生 (共有の URL・手順 JSON) で全部突き合わせる。
2. **冒涜まわりから移す:** 骨・発現・お告げ (勢力・ネクロマンシー・反響・光・腐食)・深淵のエッセンス。例外が一番多い所。
3. **オーブ類:** 変成・増強・王者・錬金・高貴・カオス・消去・神・フラクチャー。
4. **エッセンス・品質・触媒・ルーン。**
5. **今の例外の書き足しを消す。** 移し終えた関数から `if (category === …)` などを外していく。
6. **Craft of Exile と比べる** (総点検の残り 18 個)。

手順の再生 (共有の URL・動画の手順) が同じ結果になることを、各段で必ず確かめる。違う結果になる所は、どちらが正しいかを Craft of Exile とオーナーで決めてから直す。

## 決めたこと (2026-10-14 オーナー)

1. **棚に無い物 (ヴァール・可能性のオーブ・インフューザー) は移さない。** 実装は基本的にしない。
2. **動作の部品は「消す」と「付ける」を分ける。** ゲームの動きに合わせる:
   - カオス = 消す + 付ける (別々。消した側と関係なく空いている側に付く。説明文「Removes a random modifier and augments … with a new random modifier」)
   - 骨 = 未発現を足す。満杯なら消してから**消した側に**付ける (poe2wiki「If it removes a Prefix, it will add a Prefix」) → `add` に `sameSideAsRemoved` の印
   - 完全エッセンス = 消す + エッセンスの MOD を付ける (付ける側は MOD で決まる)。**付ける側が埋まっている時は、必ずその側の MOD が 1 つ消えてから付く** (2026-10-14 オーナーがゲームで確認) → `remove` に `side: エッセンスの MOD の側` (埋まっている時だけ)
   - カオスが「消す + 付ける」か「置き換え」かで違いが出るのは、空きがある時 (例: ジュエル プレ 2 / サフィ 1 でプレが消えると、サフィに付いて 1 / 2 に変わりうる)。満杯なら同じ。作る時に Craft of Exile の 3 MOD のジュエルでも確かめる
   - `replace` (1 つの部品で置き換え) は作らない (カオスと骨の違いが見えなくなるため)
   - カオスの「付ける」は、消した後に空きがある側 (プレ・サフィの両方が候補) から重みで選ぶ。どこにも空きが無ければ付かない (2026-10-14 オーナー「プレとサフィどっちも抽選できないとダメ」)。「上限超えの側の MOD に当たったら適用されない (オーブも使わない)」はゲームの決まり (2026-10-14 オーナーがゲームで確認、プレに空きがあっても同じ)。例外ではなく `remove` の制約「上限を超えている側からは消せない → 手ごと不成立」として書く
3. **ヘルプは説明文から作り直すか、比べて決める。** 今の手書きのヘルプと説明文を並べて、作り直した方が良ければ作り直す。
4. **新しい作りはウェブのエミュレーターだけで使う** (計算機は廃止予定)。
