# db とパッチノートの毎朝の見張り — 案 (2026-11-09 リサーチ長)

元の頼み: オーナー 11-09「リリース後の動きだけどさ、dbとパッチノートを毎朝チェックして追加情報がないかスケジュールしておかないとだよね　どういう形でやればいいのかタスクしといて」(black/todo.md の 1)。今は案だけ、作るのはオーナーが選んだ後 (G-20: 設計図に書く → OK → 作る)。

## 分かった事 (11-09 に見た物)
- poe2db のトップ頁 (`https://poe2db.tw/us/`、約 140KB) に、poe2db が写した公式パッチノートの頁 (`Version_0.5.5` 〜 `Version_0.5.5e`、`Version_1.0.0`) の一覧と 1.0 のカウントダウン (手元の時計で 12-12 05:00) が載っている。**新しい `Version_*` が増えた = パッチが来た** の安い印に使える (11-09 に 1 回だけ取って確かめた)。
- 今の写し: `data-cache/poe2db-pages/` 56 頁 (部位の ModsView、13MB)・`poe2db-jp/` 44 頁 (カレンシー・お告げ・エッセンス・ルーン・触媒など)・`poe2db-runeforged-<日>/`。取るのは `scripts/audit-poe2db.mjs --refresh` (1 頁 1.2 秒おき)・`build-runeforged.mjs` (1.5 秒おき)。照らしは `audit-poe2db-mods.mjs`・`audit-poe2db-tags.mjs`・`audit-poe2db-runes.mjs` (0 なら合っている)。
- 今の毎朝: 家の PC の予定のタスク `exiledesk-daily-summary` が 9 時ごろ D1 を読んで AI の評価と見解を #日報 へ (Y-45)。
- 縛り: 外の API は叩かない・公開の頁だけ (Y-52)、poe2db の取り直しは今「1 日 1 回まで」(Y-52 のスキン)。クライアントは根拠にしない (E-01)。

## 何を見るか (3 段、上ほど毎日)
| 段 | 見る物 | 取る量 | 何に使う |
|---|---|---|---|
| 印 | poe2db トップ頁 1 本 (`Version_*` の一覧) | 1 日 1〜2 本 | 新しい版が出たか。公式フォーラムのパッチノート欄も 1 本 (URL は作る時に確かめる) を足すかは決める事 ③ |
| 本取り | 印が変わった日だけ: `poe2db-pages` 56 頁 + `poe2db-jp` の 44 頁 + ルーンフォージ + 新しい `Version_*` の頁 | 約 100 本、1.5 秒おき = 3 分弱 | ModsView の JSON (系統・プレ/サフィ・段・DropChance・タグ) とベース一覧・カレンシーの説明文を前の写しと比べる。生の HTML は比べない (広告・時刻で毎回変わる) |
| 補助 | 手元のクライアントの書き出し (`scripts/refresh-client-data.mjs`) | 外へは 0 本 | Steam の更新で版が変わった時だけ。新しいベース・カレンシーの名前の早い印。根拠にはしない (E-01)、poe2db が追いついたら poe2db で決める |

## 案は 2 つ
**案 A (おすすめ): 家の PC の予定のタスクで全部回す**
- 毎朝 9:30 (9 時の AI 分析の後) に新しい予定のタスクが「印」を取り、前の日と同じなら `docs/org/research/watch/<日>.md` に 1 行「変わりなし (poe2db 0.5.5e)」で終わり。
- 変わっていたら同じタスクが「本取り」→ 今の audit 台本で比べ → 差分の md を書く。写しは `data-cache/poe2db-watch/<日>/` に日付で残す (前の日と比べるため、14 日で古い物を消す)。
- 良い所: 今ある取り直し・照らしの台本がそのまま使える。比べる物 (ModsView の JSON) が重く Workers の CPU に向かない。悪い所: PC が寝ている・落ちている日は回らない (次に起きた時に 1 回追いつく)。

**案 B: 印だけ Workers の cron、本取りは家の PC**
- server/live の cron が毎朝「印」1 本を取り、変わったら異常の控え (Y-44) に 1 行 → 9 時の AI 分析に載る。本取りと比べはそれを見たブラックが家の PC で回す。
- 良い所: PC が止まっていても「パッチが来た」は必ず分かる。悪い所: 外へ取りに行く cron が 1 つ増える (Y-42 に足す)、本取りは手で回すので遅れる、作る所が 2 か所。

## 差分の見せ方と渡し先
- 差分の md の頭に 1 行の要約、その下に種類ごとの表 (何が・どの部位・前 → 今・設計図の番号)。
- 渡し先: MOD の足し・消え・段・数値・重み・タグ、ベースの足し・消え、カレンシー・お告げ・エッセンス・ルーン・ルーンフォージの説明文の変化 → **すべてジン** (E-10・E-16 の直し、E-20 の手順)。パッチノートの文だけの話 (遊び方・新しい仕組み) → リサーチ長が要点 → ブラックがどこへ渡すか決める。流れはリサーチ長 → ブラック → ジン (部長に直接頼まない = README 3)。
- オーナーへの 1 行: 差分がある日だけ「poe2db 1.0.0a: MOD +12・ベース +3・カレンシーの文 2 つ変化 → ジンに回した」の形。置き場は決める事 ②。無い日はオーナーには出さない。
