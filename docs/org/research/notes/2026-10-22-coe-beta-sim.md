## 1. ある: 「Simulator flow」= 手順の箱を矢印でつなぐ画面
うちのツリーに一番近い。ただし **箱 = 打つ手 (Step)、線 = 条件つきの行き先 (Route)**。うちは箱 = アイテムの形 (結果)、線 = 打つ手。

### 組み方
- 左の列に「Add a step」→ 箱を引いて地図に置く (箱の右上のつまみ ⠿ で引く)。始まりの箱は **入ってくる線の無い箱を自動で選ぶ** (「Starting step [AUTO-DETECT]」、手で決めることもできる。複数あると走らせる時に止まる)。
- 箱 = 題 (Step 1 など) + 打つ手 1 つ (例 Perfect Orb of Augmentation) + 下の帯に 3 つのアイコン: **家 (最初からやり直しへ)・鎖 (別の箱へ線を引く)・旗 (完成へ)**。
- 箱の題を押すと **地図の場所が丸ごと「Step edition」の窓に入れ替わる** (地図の上に浮かべない)。中身:
  - Action mode: 何もしない / 打つ手
  - **On no valid route (通れる線が無かった時): Restart (最初へ) / Loop (同じ手をもう一度) / End (完成とみなす)**
  - 打つ手の選び方 (カレンシー・エッセンス・冒涜・触媒・神殿・フラックス…、クラフト台と同じ棚。乗せると札に値段 例 変成 0.025)
  - **Route priority order (線を調べる順、↑↓ で並べ替え)**
  - 消す・写す・題と説明。「Apply changes」で決める、「Back to layout」で地図へ戻る。
- 線をつなぐ: 箱の鎖を押す → 行き先の箱の的を押す。消す時も同じ。
- **線の真ん中の丸いつまみ** (∧ の印) を押すと「Link edition」の窓 (これも地図と入れ替わる):
  - Evaluation mode: **Passthrough (いつも通る) / Conditions (条件)**
  - Conditions は計算機と同じ「要件のグループ」: And / Or / Not・一致の数 (All など)・MOD を選ぶ・段 (Tier Any)・「Add a requirement group」
  - 線を消す・行き先を替える。
- 家・旗は **線を描かない**。押すと「Step 2 → End」の窓で「Active: Yes / No」を切り替えるだけ (戻り・完成への長い線は地図に出ない)。

### 線の描き方
- 箱から出て直角に折れる線 + 行き先に矢印。線の真ん中に条件のつまみ。曲線ではない。
- 戻り (最初へ)・完成は線ではなく箱のアイコンで表す。**合流** (同じ箱へ複数の線) は作れるが、特別な見せ方は無い (矢印が同じ箱に入るだけ、使い方のページにも合流の話は無い)。

### 費用・確率の出し方
- 上の帯: Generation type (Real-time = 走りながら地図の数が増える / Fixed = 打つ回数か完成数で打ち止め / Debug = 1 手ずつ、まだ無い)・Base cost (ベースの値段)・Store items (完成品を何個とっておくか、既定 99)・Distribution tables (MOD の出方の表を足す)・Export / Save / Load (手元に保存)。
- 走らせると左の列が **Run count・Steps ran・Items completed・Success chance %・Target・Time elapsed** と、進み (Initializing ✓ / Configuring setup ✓ / Running steps) に変わる。
- **箱ごとに ✓ 成功の数 と ✗ 失敗の数、線のつまみに通った数** が出る (画面で見た、どれも 0 のまま止まった)。
- 終わると「各 Step の数の内訳を一列に並べた表 + クラフトの費用の平均」(使い方のページの文。画面では見ていない)。
- 計算機の画面から「Create simulation」で作ることもできる。

### 難しさを隠す工夫
1. 戻り・完成は線にせず箱のアイコン (家・旗) にして、地図の線を減らす。
2. 外れた時の動きを箱ごとの 3 択 (最初へ / 同じ手 / 完成) にまとめ、失敗の枝を描かせない。
3. 線の条件は既定が Passthrough (条件なし)。条件の組み方は計算機と同じ部品なので、覚え直しが要らない。
4. 始まりの箱は自動で見つける。
5. 編集は地図と入れ替わる窓 1 つ (浮かぶ窓を重ねない)。説明は別のページ (使い方) に追い出し、画面の文は最小。
- 弱いところ: 始まりのアイテムと手が合わないと、走らせて初めてエラーの窓が出る (今回 3 回とも)。組んでいる時には教えてくれない。
- 広告: シミュレーターの画面の下に横長の広告が出ていた (NitroPay、notes/2026-10-22-ad-sites-survey.md)。

## 2. うちのツリーとの違い
| 点 | CoE の Simulator flow | うちのツリー |
|---|---|---|
| 箱が表す物 | 打つ手 (Step) | アイテムの形 (結果の見本つき) |
| 線が表す物 | 条件つきの行き先 (MOD の要件) | 打つ手 |
| 外れた時 | 箱の設定 1 つ (最初へ / 同じ手 / 完成) | 戻りの弧の線 (↩ 戻り先)・合流の線 |
| 合流 | 同じ箱に矢印が入るだけ | 合流の線・札 (&ui=next の案) |
| 線 | 直角の線 + 真ん中に条件のつまみ | 曲線、打つ手の札が線の上 |
| 数の出し方 | 走りながら箱に ✓ ✗ の数・線に通った数、最後に一列の内訳と平均費用 | まだ計算を繋いでいない |
| 試し | 無い (走らせるだけ) | 箱を押すと試し打ちの欄 |

## 3. うちのツリーに取り入れたい物 (3 つ)
1. **戻り・完成を線ではなく箱のアイコンに**: 「最初へ (家)・完成 (旗)」を箱の下の帯に置き、長い戻りの弧を描かない。地図の線が減る (シミュ部長)。
2. **走らせた時、箱と線にそのまま数を出す**: 箱に「通った人数 ✓ / 外れ ✗」、線の上の札に通った数。最後に箱の順の一列の表と平均の費用 (シミュ部長、数は解析君)。
3. **外れた時の動きを箱ごとの 1 つの設定に**: 「最初から / 同じ手をもう一度 / ここで終わり」の 3 択と、線を調べる順。外れの枝を毎回描かなくてよくなる (解析君の `back: "match"`・`"restart"` を画面で選ぶ時の形に近い。シミュ部長)。
