# ブログ記事を検索で拾われる書き方にする手引き (2026-10-22)

オーナー 10-22「SEO も考えながら文章を考えてあげたらいい、note 的な」。解析君が記事を書く時に、そのまま読んで使う物。記事の種は notes/2026-10-22-blog-topics.md (狙う言葉は同ファイルの末尾に追記した)。

## 0. 先に (調べ方と限界)
- 調べ方: 検索ツールで日英のクラフト関連の言葉を検索し、**上位に出る記事の題・見出し・日付の出し方**を読んだ (Game8、いのまるの秘密基地、Mobalytics、poe2db、Vulkk、poe-vault ほか)。Google の検索窓の候補・「他の人はこちらも検索」・検索量は**取れていない** (外の API は叩かない決まり。検索ツールは日本語の結果が薄い)。
- したがって下の「狙う言葉」は、**実際にその題・用語で記事が出ている**ことと、**ゲーム内の名前 (poe2db の日本語名)** から決めた。検索量の多い少ないは**未確認**。公開後に Search Console (導入していれば) で見て直す前提。
- 一部のページ (Mobalytics の omen-crafting) は 403 で本文を読めなかった (題は検索結果から)。

## 2. 書き方の手引き (そのまま使う 15 行)
1. **題 (title)**: 「PoE2」を先頭に、狙う言葉を前半に置き、興味を引く形 (疑問・意外性・数字) を後半に。**32 字前後** (全角、長くても 40 まで)。区切りは「｜」。例: 「PoE2 クラフトの期待値は勘と違う｜最善手は安いお告げを使わない」。
2. **説明文 (meta description)**: **120 字前後**。「何を調べて、何が分かるか」を 1 文で。狙う言葉を 1 回入れる。数字があれば 1 つ入れる。例: 「最速手で付けた時の期待値を後ろから計算すると、動画に近い打ち方は約 3,400 神、最善手は約 105 神。安いお告げを使わず普通の消去で外れを消す理由を、エンジンで 1,000 本回した結果とあわせて解説します。」
3. **最初の 100 字**: 結論を先に (「答えは◯◯。理由は…」)。読み物の調子は 2 段落目から。狙う言葉は最初の 100 字に 1 回入れる。
4. **見出し (h2)**: 4〜6 個。**問いの形か結論の形** (「なぜ完全の高貴は高いのか」「結論: 上級が 105 神で最安」)。h3 は必要な時だけ。見出しにも狙う言葉の言い換えを 1 つ入れる。
5. **表は文字で書く** (画像にしない。競合は MOD 一覧が画像で、検索に拾われない)。数字・名前は表に、解釈は本文に。表の見出しは日本語名 + 英語名。
6. **図は alt に説明を書く**。画像だけで中身を伝えない (本文にも同じ数字を書く)。
7. **記事どうしのリンク**: 各記事の最後に「関連する記事」を 2〜3 本 (同じ装備 / 同じ道具 / 次に読む物)。本文中でも初出の用語から、その用語を説明した記事へリンク。
8. **ツールへのリンク**: 記事の途中 (結論の直後) と最後に、ExileDesk の該当画面へ 1 本ずつ (例: 金の指輪で試すボタン、スパムシミュレーター)。「ここで確かめられます」の一文を添える。リンク先は exiledesk.com (旧 workers.dev は使わない)。
9. **更新日の書き方**: 記事の頭に「公開: 2026-10-xx / 更新: 2026-10-xx (PoE2 の版 0.x)」。数字を直したら更新日を変え、末尾に「更新履歴 (何を直したか)」。競合は更新日を出していない所が多く、ゲームの版で情報が古くなる分野なので **版の番号を書くことが強み**。
10. **数字の確かさを必ず書く**: 「エンジンで 1,000 回打った結果」「poe2db / CoE で確かめた」「ゲームで確認」「推定」(blog-topics の 4 区分)。根拠のない数字は書かない。
11. **日本語と英語で変える所**: 題は日本語が「PoE2 + 日本語のゲーム内名 + 興味の形」、英語は「poe2 + crafting + 物の名前 + (guide / expected cost / how to)」。英語の題は 60 字以内、説明は 150 字前後。用語は poe2db の英語のまま (GLOSSARY.md と同じ)、直訳しない。英語は更新日と版 (patch 0.x) を先頭に。日本語は「ディバイン」、英語は "divine" / "Divine Orb"。hreflang は日英の記事を相互に指す。
12. **note 的な読み物の調子を残す**: 一人称で「やってみたら…だった」を 1 段落入れる。失敗・直した話を隠さない (「前の記事で◯◯と書いたが誤りだった」)。ただし**見出しと最初の 100 字は読み物の調子にしない** (検索の人が答えを探せるように)。
13. **やってはいけない事**: 狙う言葉の詰め込み (1 記事で同じ語は自然な範囲、題・最初の 100 字・見出し・結びで各 1 回まで)。中身の薄い記事 (数字も根拠も無い、競合の言い換え)。他サイトの文の写し。数字の作り話。更新日だけ変えて中身を変えない。
14. **1 記事 1 テーマ**: 狙う言葉 1〜3 個 (主 1・副 2) に絞る。主の言葉は 1 記事だけ (同じ主の言葉の記事を 2 本作らない = 共食い)。
15. **公開前の見張り**: 題の長さ・説明の長さ・h2 の数・表が文字・リンク (ツール 2 本 + 関連 2〜3 本)・更新日・数字の確かさの札・日英の相互リンク。

## 3. 競合の観察から (真似する所 / 避ける所)
- 真似する: Game8 の「最終更新日」の出し方、いのまるの「完成品の名前 + クラフト手順解説」の題の型、見出しの「モッド一覧 / 材料 / 作り方 / まとめ」の流れ (ただし MOD 一覧は文字の表で)。
- 避ける: MOD 一覧を画像にする、日付が公開日だけ、関連記事の欄が空、「完全ガイド」と付けて中身が薄い。
- 空いていそうな所 (競合の題に見当たらなかった): **期待値・費用の数字を出した記事** (競合は手順の解説が中心)、**poe2db / CoE の重みの食い違い**、**手袋・ES 系のクラフトの費用比較**、**直した話 (誤りの訂正)**。ここが ExileDesk の強み (エンジンで回した数字)。ただし「検索で本当に空いているか」は検索量の調べができておらず**未確認**。
