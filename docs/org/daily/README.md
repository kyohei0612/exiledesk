# デイリー部長 (デイリークラフトチャレンジ)

毎日のお題をシミュレーターで組んで平均の費用で競う、デイリークラフトチャレンジの係 (オーナー 10-22)。別ページ (タブを 1 つ増やす)。構想はメモ craft-challenge の「10-22」の節が正。docs/org/dev/README.md の決まりが先。

## 決まり (10 行まで)
1. 持ち物は src/views/daily/ と docs/org/daily/。後から server/live のデイリーの所 (お題の箱・精査の待ち・順位・7 時更新・月曜リセット)・D1 の表・src/state/daily*.ts も持つ (作る時に owners.txt に足す)。
2. 今の段 = UI/UX のモック。何も使っていない皿の状態で作る: データは全部手で書いた見本 (src/views/daily/daily-mock.ts)、サーバー・シミュレーター・エンジン・相場は使わない、開発版だけ。オーナーの OK まで次の段 (中身をつなぐ) に進まない。
3. よその部の物はブラック経由で頼む: ページの入口・タブ (src/web/page.ts・src/state/web-page.ts・WebApp.vue) と共通の部品はジン部長、シミュレーターの画面を「お題の始めの形 + フラクチャー選び」で開く口はシミュ部長、サーバーの共通の所は分析君。
4. 画面の決まりは MEMORY.md の「UI の決まり」(ゲームの絵・1 つの枠・文字は最低限・枠の外で取り消す・崩れない UI・スマホは 768px 未満で縦積み) と、広告はページで数える (メモ ads-page-model、両脇に縦長の枠)。英語も一緒に作る (src/i18n、用語は GLOSSARY.md と poe2db)。
5. 構想の要点 (動かさない): お題は誰でもクラフトボックスに投稿 → オーナーの精査 → 古い順に 1 日 1 個 / 未解決は溜まる / 月曜 7 時に未解決を全部リセット / 朝 7 時更新 / 平均の費用で競う / 解決 = 完成率 90% / 段はお題ごとに緩める / 創生の樹産は 1 つまで / シミュレーターの画面から、どの MOD をフラクチャーして始めるかを選ぶ (フラクチャーの費用は数えない) / ランキング・手の公開・レシピを見る UI は後。
6. 確かめは開発版を窓なし Chrome で撮る (1660×860 と mobile)。開発版のデプロイ・確認用の Chrome・dev サーバーは使う前と返す時にブラックへ 1 行。前後のスナップで報告し、見た目の OK はオーナー。
7. 迷った所 (見せ方の案が 2 つ以上) は、作る前に案をスナップか絵でブラックへ。勝手に決めて作り込まない。
