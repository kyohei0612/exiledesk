# 古い塊の読み直し (2e952b59) が本番のリクエストを増やすか (10-23 夜、デザイン部長 3 本目の見立て。直すのは明日)

## 作り (web.html の頭の __staleReload)
- 走る時: 入口の塊 (/assets/web-*.js・.css) が読めない (error)、または後から読む部品の import() が失敗した (vite:preloadError、pwa.ts)。= 開いたままのタブ・古い HTML を持った端末が、出し直しで消えた前の版の塊を読みに行った時だけ。普通に開いて使っている人では走らない。
- 走ると: 1.5 秒ごとに `/?stale=<時刻>` (index.html) と、その中の入口の JS を取り直す。入口が 3 回続けて同じになったら 1 回読み直す。60 秒で諦めて読み直す。
- 守り: 1 回の読み込みで 1 回、1 分に 3 回まで (sessionStorage の印)。

## 本番の数え方 (server/web/wrangler.jsonc)
- run_worker_first は `/`・`/index.html`・`/web.html`・`/s/*`・`/og/*` だけ。`/?stale=…` は `/` なのでワーカーを通る = 枠に数える。`/assets/…` は静的なので数えない。
- 1 回走ると: ワーカーへ 3 回 (揃っていれば 1.5 秒 × 3) + 読み直しの `/` 1 回 = 約 4 回。Cloudflare の入れ替わりが続いても 60 秒で 40 回 + 1 回が上限。
- 人数分で増えるのは「出し直しの時に開いていて、その後で後から読む部品を開いたタブ」の数だけ。出し直しは 1 日数回、そのたびに開いているタブ × 約 4 回。普通の 1 回の訪問 (ページ・相場・分析の送り) と比べて小さい。前の作り (すぐ読み直し、1 分に 3 回まで) でも 1 タブ最大 3 回はワーカーを通っていた。

## 見立て
- 人数分に比例して常に増える作りではない (走るのは出し直しをまたいだタブだけ)。今の訪問の数なら 1 日の枠にはほぼ効かない。
- 気になる所: 出し直しの直後に開いているタブが多い時、1 タブ 4〜41 回を同じ 1 分の間に集めて叩く。
- 明日の直しの案 (どれか 1 つ、小さい順):
  1. 取り直しの間を 1.5 秒 → 3 秒にし、揃うまでの回数を 3 → 2 に (1 タブ約 3 回、上限 21 回)。
  2. 取り直すのを `/` ではなく静的な小さい版の印 (例 /assets/ の外の `version.txt`、ビルドで書く) にする。run_worker_first に無い静的なファイルなら枠に数えない (`/?stale=` は 0 回、読み直しの 1 回だけ)。
  3. 根の直し: 本番でも 1 つ前の版の塊を残す (notes/2026-10-23-keep-prev-assets.md の案)。消えた塊が無くなるので __staleReload 自体がほぼ走らない。
- おすすめは 2 (+ いずれ 3)。2 は web.html の頭とビルドの出し (vite.web.config.ts か deploy の台本) を触る。3 は最終チェック長・分析君へ。

## 10-24 にした事 (4 本目、cd82fc4a): 案 2
- web.html の頭の __staleReload は `/version.txt?t=` (静的、run_worker_first に無い) を取り直す。中身は入口の JS の道 1 行で、vite.web.config.ts の closeBundle が index.html から書く (無ければビルドが落ちる)。/web/ は sw.js が cache-first で持つので根に置いた。
- 確かめ (手元の本番の作り preview:prod --port 1464、窓なし Chrome 9334、SW の下で __staleReload() を 2 回): 印 3 回 + 入口の JS 3 回 → 3.2 秒で読み直し、Worker を通るのは読み直しのページ 1 回だけ、画面が出る・印 1→2・エラー 0。台本 scratchpad の stale-ver-check.mjs。
- 見ていない: 印が取れない時 (dev サーバーなど) は 60 秒で読み直す前の形のまま (回していない)。本番の出した直後の入れ替わり (サーバー管理人が出した直後に見る物)。
