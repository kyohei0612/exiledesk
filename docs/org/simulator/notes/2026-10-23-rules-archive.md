## 決まり (docs/org/dev/README.md の決まりが先)
- 呼ばれたら常駐 (初めて仕事が来た時にブラックが立て、そのブラックの間は開きっぱなし)。仕事はブラックから直接来て、結果の報告もブラックへ直接 SendMessage 2〜5 行 + 中身は todo.md・notes/ (オーナー 10-21)。同じファイルの仕事は順に、触るファイルは始める前に dev/touching/simulator.md に自分で書き、自分の commit で消す。自分の commit の push と開発版 (deploy:web-dev) は自分で、本番は最終チェック長 (dev/README.md の決まり 1・2・5・8)。
1. 開発版だけ (`SIM_LOCKED`)。本番に出すのはオーナーが決める。
2. 自動でやる打ち方の決まりは必ず画面に文で出す (メモ feedback-show-sim-rules)。
3. 両側の「どれか」は側ごとに分ける (sim-split-by-side)。工程ごとに 1 ページ、初心者でも分かる形 (sim-step-pages)。
4. 10-20 の決め: フラクチャーは完成品の MOD の印・何でも良い枠と妥協は無し・上限は作り直しの回数 (sim-decisions-2026-10-20)。
5. 自動で組む段は T2 以上まで。② に T1 の狙いがあってもチェックは押せ、押すと警告のポップアップ「T1 の狙いがあります。自動は T2 以上として組みます (T1 は完成しにくく計算も長い)。」[T2 以上にして自動にする] [手動のまま] (日英)。前者で T1 の狙いを T2 以上に下げて自動に (Ctrl+Z で戻せる)。フラクチャー固定の T1 は打たないので下げない (オーナー 10-20)。
6. 関門の打ち止めはベース 1 個ごとに数え、買い直したら 0 に戻す。買い直しは N 回まで (N は解析君が見本で 99% の人が収まる回数を丸めて決める)、超えた人は未完成で費用は入る (オーナー 10-20)。
7. 値段は手入力 + 検索を開くボタンだけ、取引所の自動取得は使わない (sim-no-trade-fetch)。
8. **エンジンにもエミュの画面のコードにも触れない** (src/services/craft-stage・htc・mods・items・vendor/poe2htc はジン部長、src/views/craft-stage・src/state/emulator を import しない。オーナー 10-22 深夜「コードが混ざらないように」)。線引き: 結果が変わる物 (付き方・確率・固定される MOD・打てるか) はエンジン、見え方と操作 (いつ使うか・どう見せるか) は画面 (例: フラクチャールートの「必ず成功」はエンジンの for-sim の機能、木のどの手で使い「✦ 確定」と見せるかはシミュ。オーナー 10-23)。シミュに自我はいらない: 足すのは UI/UX だけ、中身 (打つ処理・確率・当たりの判定・側・MOD の扱い) は全部エンジンの入口から取り、自分で書かない。欲しい機能・シミュ用に一部変えたい所はブラック経由でジン部長に追加の要望 (設定で切り替える形も可)、シミュが出した要望の物はシミュだけが使える (engine-sim.ts)。部品: 両方の画面で一緒の核は for-share (src/components/for-share・src/state/for-share、デザイン部長だけが直す) から使い直に書き換えない、揃えたい時だけブラック経由でデザイン部に相談、画面ごとの違い (「狙いにする」など) はシミュの側で包む / slot で足す (オーナー 10-23)。最善手・期待値の数字は解析君に頼む (ブラック経由)。
9. ツリーは「誰もがクラフトを試しやすい」ためのユーザー体験が芯で妥協しない (オーナー 10-22)。確かめは開発版にデプロイした物を本物のマウスの入力で一手ずつ触り、そのたびにスナップを見て普通の良いアプリと比べる (zoom が 1 でない 1280・1920・2560 幅も)。台本の数え (交差 0・24px 以上など) は足しで、数字が 0 でも見て汚ければ直す。報告には何で確かめたか (本物のマウス / 台本、開発版 / 手元) を書く。見た目はリサーチ長のノードエディターの見本 (research/notes/2026-10-22-tree-ui-references.md) に合わせて作り直す前提。
