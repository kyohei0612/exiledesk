# 当たりの先もツリーが伸びる件 (自動で閉じる案、シミュ 27 本目 10-25)

## 決め (10-25 オーナー、ブラック 11 代目経由) → 作った
- 流れ: オーナー「A + B 両方」→「自動で同じ形のツリーまで引っ張ってほしいな矢印」→「完成ボタンおしたら止まっちゃうでしょそもそもそっから枝分かれするんだからツリーって」(A は作らない、一度作った 7ba72f48 の A は外した) →「これ自動でやんないと分からずに同じツリーを何個も作る羽目になるぞ」(外れの戻りも自動 = 下の C も入れる)。
- 決まり: 手を決めてできた結果の箱は、木の中に同じ状態の箱があれば新しく伸ばさずそこへ自動で矢印 (tree-shape の linkSameShape、印 autoBack、戻り先の札で替えられる)。人が選ぶのは同じ状態の箱がどこにも無い時だけ (選ぶまで穴)。
  - 当たり: 先に作った、道の札 (付いている狙いの組) が同じ当たりの箱へ (sameHitOf。手の無い箱 = 狙いが揃った箱・まだ決めていない箱も行き先。古い箱が新しい箱へつながる逆向きは作らない)。
  - カオス 1 回ずつの外れ: 親の箱 (同じ手をもう一度) へ (swapJunkOf。狙いは親と同じで外れだけ替わった)。カオススパムオーブは外れの箱を作らない。
  - 狙いが消えた・外れ・外れが消えた: 前からの形の合う手のある箱へ (matchTargets)。
  - 完成は自動で付けない。狙いが揃った箱からも枝分かれできる (＋もそのまま)。
  - カオススパムオーブ (棚の上の札「スパム」) も出さない (オーナー「これならぶっちゃけカオススパムモードいらんわ。俺が間違ってた」)。use-sim-shelf.ts の TREE_SPAM_ORB = false で止めただけで作りは残す (要望が来たら true)。前に保存した当たるまでの手は開いた時に札が出る。1440 でレアの箱の＋を本物のマウスで押して札 0、カオス → 狙いにチェック → カードで手、外れ → 親・狙いが消えた → 始めへ自動の矢印。
  - 外れの箱の＋で同じカオスを足した道は特別扱いしない (オーナー「カオス足したら普通に挙動どおりでいいんじゃない 死ぬほど増えるからツリーが気づくでしょ」)。
  - 外れ・狙いが消えたの箱の「カオススパム」の近道は消した (オーナー「ハズレMODついた時の枠の中カオススパムっておかしいな消してくれ戻るボタンだけでしょ…それかプラスで枝増やすしかルートなくね」)。道は「↩ 戻る」と「＋」だけ、当たるまでは手を足す棚のカオススパムオーブで選ぶ (TreeBox の spamOk・SimTreePage の onSpam を消した)。1440 で外れの箱のボタン = ! / メモ / ↩ / 下の＋、カオススパムのボタンは画面に 0。
- 確かめ (手元 1440、台本 27 本目の scratchpad loop.mjs): 手袋 ライフ + 筋力、錬金術 → 当たり 2 つと外れの箱にカオス。b6 → b1・b9 → b2・b12 → b3 (外れ → 親)、b7 → b4・b10 → b1・b11 → b2 (当たり → 先の同じ状態)、残る「決めていない」は揃った b4 だけ。100 人回すと完成 82 (つながる前は 1)。乗せた時のカード「同じ形の箱へ自動でつないだ」、JS の例外 0。

## ① 今の木で起きる事 (手元 1440、猿の口で組んで画面を撮った。台本 27 本目の scratchpad loop.mjs)
手袋 (巨大なミット)、完成の狙い = T2 以上の最大ライフ (プレ) + 筋力 (サフィ)。白 → 錬金術 → 当たりの箱にカオス、を続けた。

```
start (白) ─ 錬金術 ─┬ b1 当たり ライフ ─ カオス ─┬ b4 当たり 筋力 (= 2 つ揃った)   ← 完成の印は付かず「＋」が出る
                     │                          ├ b5 狙いが消えた → 始めに戻る (自動)
                     │                          └ b6 外れ                     ← 戻り先は空き (人が付ける)
                     ├ b2 当たり 筋力  ← b1 の下と同じ事をもう一度組むことになる (順番違いの同じ状態)
                     └ b3 外れ
```
- **b4 (狙いが全部付いた当たり) は自動で完成にならない**。「完成」のボタンと＋が並び、＋でカオスを足すと、候補 0 のまま「狙い無しのカオス」(打った後の箱 b7) が作れて木が伸び続ける。回す時は手の無い箱で狙いが揃えば完成と数える (tree-run) ので、手を足した時点で完成が消える。
- **同じ状態の箱がくり返す**: b2 (筋力が先) の下は b1 (ライフが先) の下と同じ形をもう一度作る事になる。今の自動のつなぎ (linkSameShape) は「手のある箱」だけが行き先で、完成の箱・手の無い当たりの箱へはつながない。合流 (joinSameShape) も完成の箱に手を付けた時だけ。
- カオスの外れ b6 (ライフは残って外れが替わった = b1 とほぼ同じ状態) は戻り先が空き。形の鍵 (shapeKey) が「当たりの箱 = 外れ無し / 外れの箱 = 外れあり」で別なので、b1 へ自動でつながらない (オーナーは「戻すのはわかる」と言っているので、ここは手で付けている所)。
- ついでに見つけた物: 狙いが消えた → 始めに戻る (自動) は、スタートの手が錬金術だと戻った人がレアに錬金術を打てず止まる (精査 start:cantUse、100 人中 3 人)。

## ② 自動で閉じる案
- **A. 狙いが全部付いた当たりは自動で完成** (おすすめ): 当たりの箱を作った時、道の札 (heldSets) が完成の狙いを全部含めば done = main を自動で付け、印 autoDone (乗せた時のカードに「狙いが揃ったので自動で完成」、完成のボタンで外せる、手で外したら付け直さない)。＋は出したまま (完成の後に品質・聖別などを足したい人がいる時のため。足したら今どおり完成は外れる)。変わる所: tree-hand-plan の applyPick (linkSameShape の後に 1 行)・tree-model に autoDone の印・TreeHoverCard の 1 行・日英。エンジンの入口は要らない (道の札の数え方は木の形だけ。回す時に本当に揃っているかは今どおりエンジンの aimHeldOn で見る)。
- **B. 同じ状態の箱へは自動で合流** (A と一緒に、おすすめ): 新しくできた当たりの箱が、木の中の完成の箱・手のある箱と同じ道の札 (順番違い) なら、そこへ戻りの矢印で自動でつなぐ (今の linkSameShape の行き先に完成の箱を足す。印 autoBack で今と同じく乗せた時のカードと戻り先の札で外せる)。これで b2 の下でカオスを打てば当たりは b4 へ合流し、同じ形を 2 回組まない。変わる所: tree-shape の linkSameShape と shapesOf (完成の箱を行き先に)。エンジンの入口は要らない。
- **C. 入れ替えの外れは親へ自動で戻す**: カオスの外れ (狙いは親と同じで外れだけ替わった) は親の箱へ autoBack。オーナーが手で付けている所を省くだけで、形はカオススパムオーブ (当たるまで) と同じ意味になる。手で戻したい先が違う人もいるので、やるなら A・B の後にオーナーに聞いてから。変わる所: tree-model の setHand の既定の戻り先 (外れが消えた → 外れの前の箱、と同じ並び)。

おすすめ = A + B を一緒に。A だけでも「当たりの先が伸びる」は止まるが、順番違いの枝 (b2) は残るので B と組む。どれも「打ち方を自動で組む」(10-21 にやめた自動モード) ではなく、人が組んだ箱の印・つなぎを自動で付けるだけ。持ち物はシミュ部 (src/services/simulator/tree・src/views/simulator/tree)、エンジン・for-share は触らない。
