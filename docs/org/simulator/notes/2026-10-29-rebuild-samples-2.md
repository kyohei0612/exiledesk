## シミュの作りの穴 (直していない。直すかは別の頼み)
1. **S-51 (同じ手なら戻る) の候補に「打った後」と通り抜けの箱が入らない**: 形 (sameShape = true) も手も同じでも戻らず新しい段になる (ownerCatalyst の b9 → b3、ownerWhittle の b57 → b53)。tree-shape の sameHandReturn は shapesOf の箱だけ見る。そのため狙い無しの高貴のカオスの再挑戦の輪が組めず、オーナーの木 2 本は高貴を「☑ プレのレアリティ」に替えた (外れの箱なら戻れる)。
2. **カタリストの手「n % まで」(catHand) の結果の箱は「品質を上げた後」に数えられない**: afterQualityOf は通り抜け (pass) の箱だけ。その後の触媒の高貴の手に、前のカタリストが自動で足され、種類は完成形の最初の付いていない狙い (金の指輪では火) → 精査の quality。ownerWhittle は「最大まで」(通り抜け) にして避けた。
3. **精査の辿りの「狙いが消えた」は文で見る**: 削減で全耐性の低い段 (T4・T5、完成形は T2 以上) が付いた人は外れの箱に着く (当たりの分けは段で見る) のに、その人にエッセンスを打つと「狙いが消えた」に数え、行き先の無い unexpected が出る (ownerWhittle b60)。精査の勧め「この手を選び直して結果の箱に足す」でも箱は足されない。
4. **道の狙いの組 (heldSets) はカオスで必ず消える狙いも持っている扱い**: ✦ + 詠唱速度の箱にカオス (☑ スピリット) を打つと、消せるのは詠唱速度だけなのに、スピリットの当たりの箱が「両方ある」箱へ自動でつながった (okPcmPyY の組み直しの途中、neverHit)。木はその手をやめて高貴で足す形にした。
0. **「失敗」の印が保存・共有の code から消える (一番大きい)**: 読み込みの移し替え tree-migrate.ts の 47 行目が done を "main" しか残さない ("fail" は null)。組み直した木を開き直すと、失敗で閉じた箱が全部「行き先を決めていない」に戻る (amuB b42・b48、infinite b21・b23、bone3 b8 …)。上の表は組んだその場の数。trees.json の code を開くと未設定の箱が出るので、直した後に基準 (dev) を取り直す。オーナーの木 2 本も開き直すと同じ (失敗の箱が未設定になる)。
5. 精査の neverHit・当たるまでの stuck (30 人・1000 回) は、付きにくい T1 の狙いで運次第に出る (100 人回すでは止まり 0)。見本のアミュレット 3 本の stuck はこれ。
