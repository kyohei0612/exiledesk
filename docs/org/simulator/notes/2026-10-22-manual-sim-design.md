## 0. 芯 (決まっている事)
- **打ち方の表** (上から順に見て、最初に合った行の手を打つ) + **N 人をエンジンで回す** + **道を並べて比べる**。最善手の自動の探しはしない (10-21)。
- 正解の分からない数字は既定値 + 使う人が直せる (10-22)。お告げの倍率・MOD の重みはエンジンの stageTuning (engine.ts の `stageTuning`・`setStageTuning`) をそのまま使う。

## 1. 画面の流れ (1 段 1 ページ、広告の決まり ads-page-model)
クラフト台とは別のページ。URL は今の `?page=sim-*` の仕組み (src/web/page.ts・state/web-page.ts の SIM_STEPS) を使い回し、段の名前だけ替える。

| 段 | URL | 中身 |
|---|---|---|

## 2. 保存の形 (JSON)
台本の nextMove を、そのまま JSON に起こした形。手は今の手順 JSON (contract.ts の PlanStep: currency・omen を「+」でつなぐ) と同じ書き方にして、クラフト台の再生 (playStep) と食い違わないようにする。

```jsonc
{
  "schema": "exiledesk-route/1",
  "title": "金の指輪 サフィックス 3 (すぐ消す)",
  "start": {
    "base": "Gold Ring", "itemLevel": 82, "rarity": "rare",
    "mods": [{ "mod": "Rings/Special_genesis_tree_caster_SpellDamage", "side": "prefix", "tier": 2, "fractured": true }],
    "then": [{ "currency": "exalt" }],          // 始めの形まで打つ手 (費用に入れない)
    "cost": 0                                   // 始めの形の値段 (神)。「作り直し」の時もこれを払う
  },
  "targets": [                                  // 完成 = 全部ある
    { "key": "R", "label": "レアリティ", "mods": ["Rings/ItemFoundRarityIncrease"], "tierAtLeast": 1 },
    { "key": "C", "label": "キャストスピード", "mods": ["Rings/IncreasedCastSpeed"], "tierAtLeast": 2 },
    { "key": "A", "label": "全耐性", "mods": ["Rings/AllResistances"], "tierAtLeast": 2 }
  ],                                            // tierAtLeast = T 何以上 (1 = T1 だけ)。mods が複数 = どれか (単体耐性のどれか など)
  "rules": [
    { "if": [{ "t": "count", "op": "=", "n": 0 }], "do": [{ "currency": "chaos" }] },
    { "if": [{ "t": "room", "side": "suffix", "op": "=", "n": 0 }], "do": [{ "currency": "annul" }] },
    { "if": [{ "t": "junk", "side": "suffix", "op": ">=", "n": 1 }], "do": [{ "currency": "annul" }] },
    { "if": [{ "t": "has", "key": "R", "is": "none" }], "do": [{ "currency": "exalt_greater", "omen": "OmenofDextralExaltation" }] },
    { "if": [{ "t": "has", "key": "C", "is": "none" }],
      "do": [{ "quality": { "catalyst": "catalyst_speed", "atLeast": 20 } },
             { "currency": "exalt_perfect", "omen": "OmenofCatalysingExaltation+OmenofDextralExaltation" }] },
    { "if": [], "do": [{ "currency": "annul" }] }   // 条件なし = いつも
  ],
  "run": { "people": 100, "budget": 2000, "maxSteps": 20000, "restarts": null },
  "prices": { "chaos": 71.892 },               // 直した値段だけ (高貴建て)。無い物は今の相場
  "tuning": { }                                // 直した重み・倍率だけ (stageTuning の形)。無ければ既定
}
```
- 行の `do` は 1〜3 手の並び (カタリストで品質を上げてから打つ、餌を付けてからエッセンス、のような「セットの手」)。`quality` は「品質が N% 未満の間カタリストを 1 個ずつ」(台本の while と同じ)。
- 特別な手: `{ "restart": true }` = 作り直し (始めの形から、start.cost を払う)、`{ "giveUp": true }` = その人はやめる (未完成、使った分は入る)。
- どの行にも合わない = その人は「表に無い形」で止まる。結果に回数と、最初に止まった 1 人のアイテムを出す (表の穴の見つけ方)。
- 共有は今のレシピの共有 (recipe-share.ts の URL に詰める形) を、この JSON で。

## 3. 表の条件 (最初は 5 種類 + いつも)
台本 3 本の nextMove はこの 5 つで全部書ける (下の 7 で突き合わせ)。

| t | 意味 | 引数 | 台本の元 |
|---|---|---|---|
| `count` | 狙いが今いくつあるか | op・n (side で側を絞れる) | `!got.length` |
| `has` | 狙い X が: ある / 無い / 低い段で埋まっている | key・is (`yes` `none` `blocked`) | `has`・`blocked` |
| `junk` | 外れ (狙いでも固定でもない MOD) の数 | side・op・n | `junkSuffix`・`!isTarget` |
| `room` | 側の空きの数 | side・op・n | `suffixes.length >= 3` |
| `mod` | 狙いの外の MOD (餌・品質の最大値・紋章など) がある / 無い | mod・is | `hasMQ` |
| (空) | いつも | — | 最後の行 |
- 1 行の条件は全部そろった時 (かつ)。「または」は行を 2 つに分けて書く (画面が単純で済む)。
- **おすすめ: 最初はこの 5 つで出す。** 2 弾目の候補は `quality` (品質が N% 未満)・`mark` (下の段の印)・`spent` (ここまでの費用が N 神を超えた → 作り直し、の判断)。

## 4. 平均の出し方 (C-1)
**おすすめ: 主の数字は「1 個あたり = 全員が使った合計 ÷ 完成した数」**、横に完成率・中央・90%・±95% の幅。
- 解析君のノートと同じ数え方 (未完成の人の使った分も入る)。打ち止めで「完成した人だけの平均」が安く見える罠を避けられる。
- 打ち止め: 既定 **2000 神** (今までの 300 人の計算と同じ)、直せる。上限の手数 20,000 (堂々巡りの見張り、画面には出さない)。作り直しの回数の上限は既定なし (10-20 の「上限は作り直しの回数」を使う人が入れられる)。
- 外れ値: 既定は **切らない**。「上下 3 人を外して見る」の切り替えを 1 つ (配信者の言い方そのまま [238:12])。切った時は札に「上下 3 人を外した」と出す。
- 人数: 既定 **100 人** (配信者の 30〜100 の上、1〜4 秒で終わる)。「+200 人」で足して 300 人へ (同じ seed から続けるので、足しても前の 100 人は同じ)。±95% の幅が平均の 1 割を超える時は「人数を足すと幅が狭まる」を 1 行。

## 5. 分岐とリカバリーの書き方 (C-2)
**おすすめ: 分岐は「状態で書く」だけで始める。** 段の番号や「前に何を打ったか」は持たない。
- 台本 3 本はどれも状態だけで決まる形だった (金の指輪の枝 2・3・4 も、表から自然に分かれる)。リカバリー (外れたら消去・全部消えたらカオスに戻る) も、行の上下の順で書ける。
- 配信者の靴 (結晶化 + エッセンスの 50% の賭け → 負けたらリカバリー → 駄目なら作り直し) も、ほぼ状態で書ける: 「紋章がある (mod)」「移動スピードが低い段で埋まっている (has blocked)」「プレフィックスの外れ」で分かれる。足りない時だけ 2 弾目の **段の印** (`do` に `{ "mark": "賭けの後" }`、条件 `{ "t": "mark", "is": "賭けの後" }`) を足す。
- 作り直しは手の 1 つ (`restart`)。「ここで作り直す方が安いか」は 6 の行ごとの数字で見る。

## 6. 途中の期待値 (C-6、配信者の A-8 のマルコフ連鎖の代わり)
**おすすめ: 行ごとに「この行を通った時から完成までに使った神」の平均を、回した N 人から数えて出す。** 計算 (動的計画法) はしない、回した結果を数え直すだけ。
- 1 人の記録で、行 r を通るたびに「その時の使った額」を控え、完成した時の額との差を足す。未完成で止まった人は打ち止めまでの差 (= 4 と同じ数え方)。
- 「ここからの残り」が「最初からの 1 個あたり + 始めの費用」より大きい行に ⚠「ここは作り直しの方が安い」。配信者の言う「ここは消去で 1 からやり直した方が得」がこれで見える。
- 行ごとに他に出す物: 通った回数・その行で使った神 (費用の重い所 = 金の指輪のレアリティ T1 の 2.3% のような所が一目で分かる)。
