## 確かめた物
- 画面 (窓なし Chrome、直した後に同じ手順で): 打つ → Esc → 保存済み・ページは残る / 札を消す → ツリーの Ctrl+Z で札が戻り文は残る / 読み込み直しで文・場所・大きさが残る / 試し打ちを開くと窓が欄の左へ / 題のダブルクリックで最大化 → 題を引くと 360×420 に戻る / 左端へ引くと行き先が出て半分 / 最小 320×260 でメモ欄 96px / ＋ カレンシーで棚を押すと「メモにある」に出る、Esc で選び窓だけ閉じる / ＋ MOD で探す欄に入っている / 札を押すと箱 2 つが光る / 最小化 → 帯の「メモ」で同じ所に戻る / 英語。
- 押せる物の数え (台本): ふつう 320×260 で 16 個・最大化で 24 個、24px 未満 0・重なり 0・隠れ 0 (選び窓を開いた時の「隠れ」は下の札が選び窓に覆われている物で、inert にした)。
- 見張りのテスト・外の正解は無し。型チェックと入口の見張り (check-engine-entry: 増えた所なし) は通った。

## 残り
- 箱のメモ (右の欄の「メモ」= TreeNote) とこの窓のメモが別の物で、名前が同じ。窓に箱のメモの一覧を出すか、名前を分けるかはオーナーに聞く。
- 窓は 1 つだけなので「前へ出す」は無い (ツリーより常に上)。

## 追記 (10-22 夜): オーナーの Chrome で動かない・最大化から戻せない / 閉じられない (a5bbed4d・e555ec68)
- 原因: html に zoom (WebApp.vue の fitZoom、1920 幅で 1.16・2560 幅で 1.54・1280 幅で 0.85) が掛かっているのに、窓の位置・大きさを innerWidth・マウスの座標 (実ピクセル) のまま CSS ピクセルに使っていた。最大化で窓が 1.16 倍 (1920 幅で 2221px) に広がり、閉じる・元に戻すが画面の右の外へ出た。動かすのも 1.16 倍の速さでずれた。前の確かめは 1660 幅 (zoom 1) だけだったので出なかった。さらに最大化の大きさを出す computed が画面の広さの変化を拾わず、幅を変えると前の広さのまま残った。
- 直し: 窓は utils/zoom.ts の toCss で割った広さ・座標を使い、広さは ref に持って resize で読み直す。ツリーの箱のドラッグ・空き所の送り・引っ張りの先・Ctrl + ホイールの中心も同じく割る (use-tree-view.ts・SimTreePage.vue)。Esc はどこを押していても先に最大化・半分を元に戻す。
- 確かめた物 (開発版 web-dev を本物のマウスの入力 = devtools の click・drag・press_key で): 1920×1000 (zoom 1.157) で、最大化 → 窓 1920×1000・閉じる / 元に戻すが画面の中で一番上 (elementFromPoint) → Esc で元に戻る (ページは閉じない) → 題を引くと題の真ん中がマウスの所にぴったり (884, 355) → ダブルクリックで最大化 → 元に戻す → 最大化 → 閉じる。1280×720 (zoom 0.85) と 2560×1300 (zoom 1.54) でも最大化が画面ちょうど・ボタンが押せる、最大化から題を引くと元の大きさでマウスの下に付く。スナップは共有メモ tree-memo-zoomfix-2560.png。
- 教訓: 窓・ドラッグの確かめは 1660 幅だけでなく、zoom が 1 でない幅 (1280・1920・2560) でも本物の入力で触る。
