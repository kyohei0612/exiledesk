# 失敗した時の挙動の洗い出しと作り込みの案 (シミュ 30 本目、10-26)

オーナー 10-26「失敗時の挙動をかなりしっかり作りこまないとダメだね」。作るのはオーナーが選んでから。
洗い出しは読むだけのサブエージェント (コードの行は下の各項)。決着済みの決め (sim-decisions・README の決まり) は変えない前提。

## 今どうなっているか (失敗の種類ごと)

| 種類 | 今の箱と自動の行き先 | 人が選べる戻り方 | どこへ戻るかの見え方 |
|---|---|---|---|
| ① 外れ (junk) | 足す手は 当たり + 外れ、カオスは + 狙いが消えた (tree-model OUTS_OF)。1 回ずつのカオスの外れは親の箱 = 同じ手へ自動 (swapJunkOf)、ほかは同じ形の外れの箱へ自動 (linkSameShape、印 autoBack) | PC: ↩ 戻るで箱を押す / 帯の ↩ 始めに戻る / 戻りが無ければ＋で次の手。スマホ: 次の手・同じ手をもう一度・始めに戻る・ほかの箱へ | PC: 札「↩ 名前」+ 自動は「狙い同じ」、線は乗せた時だけ。スマホ: 文 + 戻り先のカード (3a175b2c) |
| ② 狙いが消えた (lost) | 消せる狙いを持って着く人がいなければ箱を作らない (noLost)。既定は始めへ (autoBack 無し)、同じ形の箱があれば付け替え | ① と同じ | PC: 「↩ 始めに戻る」。スマホ: チップが光るだけで文が無い |
| ③ 外れが消えた (junkGone) | 既定は外れの前の箱。外れの箱の下でなければ 道に当たりあり = MATCH (同じ形の箱、無ければ MATCH のまま) / 当たり無し = 戻り無しで＋ | ① と同じ | 「〈箱〉ほか n か所」「行き先の箱が無い」 |
| ④ その箱で打てない | 手の窓は「この箱では打てない: 理由」で使えない。回す時は当たりの狙いがもう付いていれば当たりへ (heldHitOf)、ほかは止まり。精査 cantUse | 手を替える・戻り先を替える | 手の窓の 1 行、精査の帯 (PC だけ) |
| ⑤ 当たるまでが当たらない | 上限の無い手は上限 (5000 回) で止まり。上限のある手は形の合う箱へ (unexpected)、無ければ止まり。1 人 20000 手 / 2000 神で打ち止め (未完成・費用は入る) | 上限を変える・手を替える | 止まりの札・精査 |
| ⑥ 100 人回しの止まり | 次の手も戻りも無い・打てない・合う箱が無い・分かれ目の行が無い・輪が 1000 回、など。PC は止まった人が出た所で止めて寄る | 止まった箱を直して回し直す | PC: 帯「n 人目で止まった」+ 赤い札、理由は乗せた時の title だけ。スマホ: 理由と戻ってきた箱を本文に |
| ⑦ 着いた箱の形が違う (settle) | 結果・戻り先に着いたら形 (狙いの組 + 外れの有無) の合う箱へ移る。moved は数えるが画面に出ない | ― | 出ない (矢印の先と実際に進む箱が違っても分からない) |
| ⑧ フラクチャーの外れ | 当たりだけ、固定できる MOD が 2 つ以上なら「2 回外れて 1 回当たり」の費用 | ― | 手の窓の文だけ、結果のまとめに作り直しの回数が出ない |

## 迷いやすい所 (コードとメモから)
1. 精査の carry の文が「戻り先を分かれ目の箱 (打たずに分ける) に」と勧めるが、分かれ目を作るボタンは 10-25 に外した = 勧める直し方が画面でできない (tree-check.ts:269)。→ 直すべき不具合
2. 自動でつながった外れの箱から枝を伸ばすには、先に × で戻りを外さないと＋が出ない (TreeBox の free)
3. 戻りを足しただけで「狙いが消えた」の箱が増える (setBack → healLost)。何も言わずに増える
4. 矢印の先と、回す時に実際に移った箱が違っても画面に出ない (settle・moved)
5. PC の止まりの理由は乗せた時の title だけ (スマホは本文に出る)
6. スマホには精査 (テストラン) の結果が無い。cantUse・carry・noMatch がスマホでは見えない
7. PC とスマホの食い違い: 完成の判定 (スマホの completes はフラクチャーの印を除く、回す時の goalsHeld は全部見る)・「同じ手をもう一度」はスマホだけ・「ほかの箱へ」でスマホは始まり・分かれ目を選べない・狙いが消えた → 始め の文がスマホに無い

## 作り込みの案 (オーナーが選ぶ)
- **案 1 (揃える・見せる、小さめ)**: 種類ごとの既定の行き先を 1 行の文で箱に出す (決まり 1「自動の打ち方は文で」)。戻り方は PC・スマホとも 次の手 / 同じ手をもう一度 / 始めに戻る / この箱へ / 完成 の 5 つに揃える (PC に「同じ手をもう一度」)。戻り先はいつも名前 + そのアイテム (PC は乗せた時のカード、スマホは開いたまま)。迷いやすい所の 1・5・7 を直す
- **案 2 (案 1 + 回した結果を箱に返す)**: 回した後、失敗の箱ごとに「n 人がここへ来て、m 人は〇〇へ移った (settle)」「止まり n 人: 理由」を本文に出す (PC も title でなく本文)。スマホにも精査の一覧 (足りない所) を出す。2・3・4・6 も直す
- **案 3 (案 2 + 失敗の箱を最初から組む)**: 手を置いた時に失敗の箱の行き先を先に聞く (「外れたらどうする?」を手の窓の中で 5 択)。既定は今の自動のまま、聞かれた所だけ変える。スマホの ② を PC にも持ってくる形
- おすすめ: 案 2。1〜7 の迷いを全部塞げて、木の作り (エンジン・回し方) は変えない。案 3 は手を置くたびに 1 問増えるので、慣れた人には重い

## スマホでタップした時の形 (絵は共有メモ sim30-tap-A/B/C.png、元は sim30-phone-tap-mock.html)
- A その場で開く: 一覧の行・図の箱を押すと、その行の下に手・結果の行き先・今の MOD が開く。「ここで答える」で質問へ。良: 文脈が切れない。悪: 一覧が縦に伸びる、図から押すと一覧の行へ送られる
- B 重ね窓 (下から): 押すと下から窓が出て中身を全部 (アイテム・手・結果の行き先と割合・木の中の位置の小さな図)。閉じれば元の場所・スクロールのまま。良: 一覧・図・戻り先選び・失敗の箱で同じ部品を使える、省略しないで全部出せる。悪: 下の画面が隠れる
- C 図が主役: 上に大きな全体図 (2 本指で寄る)、押した箱の中身を図のすぐ下に。良: 木の形と中身を同時に見られる。悪: 小さい箱を押しにくい、文の一覧が無くなる
- おすすめ: B (オーナー 10-26「やりづらかったらオーバーレイで見させてもおk」と合う、1 つの部品で全部の入口をまかなえる)

## 戻り方の文は「n 段目へ戻る」に揃えた (オーナー 10-26、シミュ 30)
オーナー「始めに戻るはなんかややこしい話だから普通にどこに戻るかいつも通り書く感じでおけ…1段目へ戻るとかにするか？全て、矢印は違うから段が同じもどり方でも」
- 戻り方の文は全部「↩ n 段目へ戻る」(同じ手をもう一度・始め・自動・選んだ箱)。段は画面の段 (箱の高さ ÷ 段の間、tree-fail の stepOf)。親をたどる深さではない (整列は揃った狙いの数で段を分けるので、深さ 2 の箱が 3 段目に並ぶ)。PC の箱の下の札・戻り先を選ぶ帯のボタン・スマホのボタンも同じ。スマホは矢印が無いので行き先の名前を添える (「↩ 3 段目へ戻る: 当たり スピリット」)
- 「狙いが消えた」の既定の戻り (始め) をやめた。戻り先は人が選ぶ (同じ形の箱へは自動の矢印)。始めの箱もほかの箱と同じく形を比べる (狙いを持った人は 1 段目へ戻せない)
- 英語: GLOSSARY に「段」の訳は無い。案は「Back to step n」(スマホは「Back to step n: <名前>」)。決まったら GLOSSARY に足す
- スマホは持っている物の絵を出さない (下の帯で「使う」を選ぶ形のまま)
- 追い (オーナー 10-26「ハズレや狙い残った消去とかの設定の道でも戻り先の日本語は●段目へ戻るで」「狙い残った時とかの日本語は、再度挑戦にしたら分かりやすいかな」): 外れ・狙いが残った・自動の矢印も例外なく「n 段目へ戻る」。同じ手を打ち直しに戻る道 (戻り先の箱の手 = この箱を出した手、tree-fail の isRetry) は「↩ 再度挑戦 · n 段目へ戻る」。PC の箱の札・乗せた時のカード・戻り先を選ぶ帯・スマホのボタンも同じ。英語は GLOSSARY に無いので案「Retry · Back to step n」
- 開発版の見本は白紙から今の作りで組み直した「見本 3: 不在のアミュレット B」1 つ。始めの高貴は狙い無し (オーナー「分かりやすいように高貴で狙わないようにして」、dev-recipes.ts)
