# ③ の始め方 = どの道か (S1c の表、シミュ部長 2026-10-20)

オーナー 10-20: 「白から作る費用」のリロールの数え方は新しく決めず、① スパムシミュレーターの道 (エンジン部 route-race.ts) と ② 増強スパムの決まり (メモ sim-decisions-2026-10-20 の 10-21) に合わせる。
今の式は use-sim-calc.ts (calc)・use-sim-starts.ts (startCost)・keep-compare.ts・sim-greater.ts。直すのはこの表を確かめた後 (開発部長)。

## スパムシミュレーターの道 (route-race.ts の routeRun、打つのは applyCurrency)
| 道 | 始め | 1 手の決まり |
|---|---|---|
| 増強 | 白 → 変成 | 狙いの側に MOD があれば消去、空いていれば増強 (狙いが付くまで)。反対側は見ない (付いても消さない) |
| カオス | MOD 1 つのレア (狙い以外) | 狙いが付くまでカオス |
| 高貴 | MOD 0 のレア | 0 なら高貴 + 偉大な高貴のお告げで 2 つ、MOD があれば消去 (0 に戻す) |

## ③ の始め方と道
| ③ の始め方 (SIM_STARTS) | 今の式 | 合わせる道 | 直し |
|---|---|---|---|
| 白から (フラクチャーの候補を作る所) | 完全変成 + (完全増強 + **消去 × 2**) × **1 ÷ pHit** + 王者 + 高貴 × (1 − p) + 骨 + フラクチャー、÷ フラクチャーの当たり | **増強の道** (狙い = フラクチャーの候補、どれか 1 つ) | リロール分 (増強・消去・変成の回数) を増強の道に。消去 × 2 と 1 ÷ pHit をやめる。王者・高貴・骨・フラクチャー・÷ 当たりはスパムではないので今のまま |
| 白から (反対側の狙い、マジックで一緒に揃える = keep の together) | magicLoopCounts(p, q, share) − 候補だけのループ | **増強の道を両側に** (② の増強スパムの決まり: プレ 1・サフィ 1、側ごとに独立) | 入口に「両側 1 つずつの増強の道」が要る (下) |
| 白から (反対側の狙い、固定してからカオス = keep の chaos) | 固定 + 1 MOD のレアにカオス、1 ÷ (カオスの当たり) | **カオスの道** (始め = 固定 1 つ + 外れ 1 つのレア。固定は消えない) | 入口に「始めのアイテムを渡すカオスの道」が要る (下) |
| 白から (グレーターエッセンスを巻き込む道、sim-greater) | magicLoopCounts(p, q, share) + エッセンス + 壁 + フラクチャー ÷ 当たり | 増強の道を両側に (上と同じ) | 上と同じ物で |
| 白から (② に増強スパムの狙いがある = wholeRoute) | 式なし (⑤ の答えで白から全部) | ② の決まりどおり | 変えない |
| フラクチャーの MOD 付きレアを買う (four) | (ベース代 + フラクチャー) ÷ 当たり + 反対側はカオス | スパム無し (反対側だけカオスの道) | 反対側のカオスを上の物に |
| フラクチャー済みを買う (fractured) | ベース代 + 反対側はカオス | 反対側だけカオスの道 | 同上 |
| エミュレーターの状態から (item) | 式なし | — | 変えない |

- 高貴の道 (MOD 0 のレア・偉大な高貴・消去) は今の ③ のどの始め方にも出てこない (③ は高貴を「1 つだけの時に 3 つにする 1 回」だけ使う)。足すかは決めない。
- 解析君の突き合わせ (step4-formula-entry.md): 今の式は手袋 −48%・靴 −52%。ずれの元はリロールの数え方。増強の道 (= magicLoopCounts(p, null, share) と同じ打ち方) なら式とエンジンが 3% 以内。

## 入口に足りない物 (ジン部長へ、名前の案)
今の engine.ts は route-race を出していない。③ は値段を入れるたびに出し直すので、何百人打つ物より平均の回数が欲しい。
1. `spamCounts(data, item, route, grade, targets, opts?)` — 道ごとの「着くまでの平均の使った物 (鍵 → 個数)」と着いた割合。routeRun と同じ決まり。
   - route = `augment` / `chaos` / `exalt`。item = 始めのアイテム (白・ルーンを差した白・固定 1 つ + 外れ 1 つのレア)。
   - targets = 側ごとに 1 つずつまで (増強の両側 = ② の増強スパム。プレとサフィは独立、両側が当たりで終わり)。
   - 平均は打って数える (人数・上限は opts) か、式 (magicLoopCounts と同じ形をエンジン側に) のどちらでも。数字は解析君が route-race の 1,000 人と並べる。
2. 今の `routeRun` に始めのアイテムを渡せる形 (prep の代わり) — 1 が無理な時の代わり。

## 直した (2026-10-20、S1c の直し)
- ③ 白から の候補作りのループ: 候補 1 つ = 入口の spamCounts (増強の道、300 人、狙い・段・等級・ルーンごとに覚える)、候補 2 つ以上 = 【仮】同じ打ち方の式 magicLoopCounts(当たりの和, null, 側の割合) (spamCounts が「どれか」を受けたら差し替え)。内訳は 変成・増強 (リロール)・消去 (リロール) の平均。
- ③ の 2 人に 1 人・買う値段までに作れる割合 (self-craft-dist): ループを同じ打ち方 (markov、反対側は見ない) に。前の「増強 1 + 消去 2 を当たるまで」(reroll) は消した。
- 変えていない (同じ決まりの式のまま): 反対側を「マジックで一緒に揃える」= magicLoopCounts(p, q, share) (解析君の突き合わせでエンジンと 3% 以内)、「固定してからカオス」= 1 ÷ カオスの当たり (カオスの道そのもの)。
- 画面の数字 (同じ貼り付け 鉄の指輪・雷ダメージ T3 フラクチャー、開発版の値段): 白から 186 → 157 神 (消去を毎回 2 つ数えていた分が減った)。ほかの始め方は同じ。手袋・靴の突き合わせは解析君に。
