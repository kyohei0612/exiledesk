# ツリーの 100 人回しの核 tree-run.ts の入口 (解析君、2026-10-23)

頼み: ブラック (オーナー 10-22、11/10 までの ①)。設計 = docs/org/simulator/notes/2026-10-22-manual-sim-design.md の 4 節。受け持ち: **tree-run.ts は解析君、それを呼ぶワーカーと画面はシミュ部長**。
打つのは全部エンジンの入口 (applyCurrency・fillCatalyst 経由)。結果の分け方はシミュ部長の tree-sample.ts の outcomeOf・aimsOf をそのまま使う (同じ分け方で見本と回しが食い違わないように)。

## 入口
```ts
// src/services/simulator/tree/tree-run.ts
export interface TreeRunOpts {
  n: number;                         // 人数 (裏は 100、確かめは 300)
  seed: number;                      // 同じ seed なら同じ結果 (mulberry32)
  price: (key: string) => number;    // 値段のキー (カレンシー・お告げ・カタリスト・骨・エッセンス) → 神。無い物は 0
  startCost?: number;                // 始めの形の値段 (神)。始まりの 1 回だけ払う (作り直しは今の TreeDoc に無いので未対応)
  capDiv?: number;                   // 1 人の打ち止め (神、既定 2000)
  capSteps?: number;                 // 1 人の手の上限 (既定 20000)
  start?: (rng: () => number) => StageItem; // 始めのアイテム (既定 = sampleOf の始まりと同じ: レア + フラクチャーの指名)
  onProgress?: (r: TreeRunResult) => void;  // every 人ごとに途中の結果 (箱の「通った人数」がその場で増える見せ方用)
  every?: number;                    // 既定 10
}
export interface BoxStat {
  reach: number;     // 1 回でもここに来た人数
  visits: number;    // 来た回数の合計 (1 人あたり = visits / reach)
  costIn: number;    // ここに着いた時のそれまでの費用の平均 (神、来た回ごと)
  remain: number;    // ここから完成 (か打ち止め・止まり) までの費用の平均 (神、来た回ごと)
  warn: boolean;     // remain > startCost + perItem (作り直しの方が安い、設計の ⚠)
}
export interface TreeRunResult {
  n: number; finished: number; main: number; compromise: number;
  capped: number;                    // 打ち止め (神か手の上限)
  stuck: number; stuckAt: Record<string, number>; // 組んでいない芽・打てない手で止まった人 (箱 id ごと)
  perItem: number;                   // 1 個あたり = 全員の合計 ÷ 完成数 (完成 0 なら NaN)
  meanFinished: number; median: number; p90: number; // 完成した人の費用
  uses: Record<string, number>;      // 1 人あたりの個数 (値段のキーごと、カタリストも)
  boxes: Record<string, BoxStat>;
}
export function runTree(data: PatchData, doc: TreeDoc, opts: TreeRunOpts): TreeRunResult;
```

## 1 人の回し方
1. 始まりの箱に始めのアイテムで立つ (費用 = startCost)。
2. 着いた箱を記録 (来た回・その時の費用)。`done` があれば完成 (main / compromise)。`back` があればその箱へ飛ぶ (アイテムはそのまま、費用は増えない)。`hand` が無ければ「止まった」。
3. 手を打つ: カタリストは fillCatalyst で最大まで → 本体。repeat (当たるまで) は当たりの札のどれかが新しく付くまで繰り返す (tree-sample の playHand と同じ形。個数を数えるために同じ流れを tree-run の中でたどる)。
4. 打つ前と後を outcomeOf で分け、矢印の先から同じ種類の箱 (当たりは付いた札と同じ aim) を選んで進む。合う箱が無ければ「止まった」。
5. 費用 = 使ったカレンシー + お告げ (omensUsed) + カタリストの個数 × 値段。capDiv か capSteps を超えたら打ち止め。

## まだの物
- 作り直し (`to: "restart"`) と「形の合う箱へ」(`match`) は今の TreeDoc に無いので未対応。入ったら足す。
- tree-sample.ts の playHand に個数を返す口 (onUse) があれば、tree-run の中の同じ流れを消して 1 つにできる (シミュ部長に頼むかもしれない)。

## 確かめ (予定)
- 見本 2 本 (ES 手袋のプレフィックス 3 つ = 105 神、金の指輪のサフィックス C = 220 神) と同じ打ち方をツリーで組み、scripts/analysis/check-tree-run.mjs で今の台本の数字と並べる (1 割以内を目安、ずれは % で書く)。

## 追記: 作った物と確かめ (2026-10-23)
- 本体 `src/services/simulator/tree/tree-run.ts` (runTree・MATCH)。型チェック 0、入口の見張り (check-engine-entry) 増えた所なし。
- **形の合う箱へ (match) を足した**: 箱の `back` に `"match"` (MATCH) を書くと、今のアイテムの形 (付いている狙いの組 + 外れがあるか) と同じ形の箱へ飛ぶ。箱の形 = 始まりから親をたどった当たりの札の組 (+ 外れの箱なら外れあり)、手のある当たり / 外れの箱だけが行き先。狙いが 0 なら始まりへ。消去で「どの狙いが消えたか」で行き先が変わる道 (金の指輪 C) はこれが無いと組めない。TreeDoc の型は変えていない (back は文字列のまま)。画面で選べるようにするのはシミュ部長。
- 突き合わせ `node scripts/analysis/check-tree-run.mjs all 300` (入口の束 `_tree-run-entry.ts`、7 秒):
| 見本 | ツリー 300 人 | 前の台本 300 人 | ずれ | 個数 (ツリー / 台本) |
|---|---|---|---|---|
| ES 手袋のプレ 3 つ (左側の高貴 + 上級) | 105.06 神・完成 100% | 105.14 神 (es-gloves-ev.mjs) | −0.1% | カオス 654.5 / 654.4、上級 65.0 / 65.1、消去 63.0 / 63.1 |

  中央・90% も同じ (ES 73.3 / 249.6、指輪 165.5 / 451.1)。前の台本は状態で手を決める作り、ツリーは箱と矢印で同じ打ち方を組んだ物 (外の正解ではなく、2 つの作りの突き合わせ)。
- 気付き (⚠ のぶれ): 指輪 C で ⚠ が 2 箱 (jRA 223.7・ra_l 242.2 > 1 個あたり 220.5、始めの費用 0)。通った人が 85〜102 人と少なく、ここからの残りのぶれで点いた形。設計の決まり (残り > 始めの費用 + 1 個あたり) のままだと 100 人ではよく点滅する。案: 来た回数が少ない箱 (例: 30 回未満) は出さない・1 割の余裕を持たせる、のどちらか → シミュ部長と決める。
- まだ: 作り直し (restart、始めの費用を払う)、300 人の幅の 1 行、onProgress をワーカーで使った時の速さ (Node で 300 人 2.6〜3.7 秒)。
