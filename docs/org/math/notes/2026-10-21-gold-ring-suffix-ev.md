# 金の指輪のサフィックス 3 MOD の期待値 (オーナーの打ち方、エンジンで回した、2026-10-21)

題材: 動画 kQROcbbeR1M (調べの元 docs/org/research/notes/2026-10-21-gold-ring-mods.md)。台本 `scripts/analysis/gold-ring-suffix-ev.mjs` (入口の束 `_gold-ring-entry.ts`)。
数字は全部 **エンジン (src/ の applyCurrency = 開発版と同じ物) で打った結果**。台本が決めるのは「次にどの手を打つか」だけ。自前の確率の計算はしていない (外の正解との突き合わせもまだ。下の「確かめた物」)。

## 結論 (先に)
- **1 個あたり 約 500〜570 神**。打ち止め 2000 神で完成 96〜100% (触媒の高貴に上級か完全を使った時)。通常の高貴を使うと 1 個 800〜2200 神・完成 58〜88% で、明らかに悪い。
- 一番良かったのは **触媒の高貴に完全の高貴 + 素の右側の高貴に上級** (品質 20% で 528 神、40% で 492 神、どちらも完成 100%)。ただし上級 + 上級 (546〜599 神) との差は 50 人の幅 (±25%) の中で、**決着していない**。
- 費用の元は「サフィックス 3 つで外れ → 消去 → 狙いも消える → 全部消えてカオスに戻る」の繰り返し (1 人平均 30〜60 回戻る、カオス 1,100〜1,900 個)。特に **素の右側の高貴でレアリティ T1 が付くのは 1 回 2.3% (上級)** しかなく、枝 3・4 はここで高貴と消去を大量に使う。
- 枝 (カオスで最初に付いた物) の違いは小さい。どの枝も結局何十回もカオスに戻るので、最初の枝はほぼ効かない。

## 始まりと狙い (決めた形)
- 金の指輪 ilvl 82 のレア。プレフィックスにスペルダメージ (グリフの、創生の樹のキャスター `Rings/Special_genesis_tree_caster_SpellDamage`) を **T2/8 (30–34、MOD レベル 71)** でフラクチャー。
  - **食い違い**: オーナーは「スペダメ T1 フラクチャー」と言うが、動画の 30–34 は poe2db で T2/8 (T1 は 82 レベル)。動画に合わせ T2 にした。プレフィックスはフラクチャーで動かないので、T1 でも T2 でもサフィックスの計算は同じ。
  - この MOD は普通の置き場に無く重み 0 なので、エンジンの startFrom では付けられない (「この手では付かない」)。始めの形だけ stage-core の `makeStageMod`・`withMod` で置いた (入口に無い物を借りたのはここだけ)。
- カオススパムを始める形 = **動画 ④a の 2 MOD** (フラクチャー + 乱数の MOD 1 つ。乱数の 1 つは通常の高貴 1 個で付けた)。カオスは非固定の 1 つを入れ替え続ける。
- フラクチャーまでの費用・始めの高貴 1 個は 0 (計算の外)。
- 狙い: レアリティ (サフィックス、考古学の) T1 / キャストスピード T2 以上 / 全ての元素耐性 T2 以上。プレフィックスは何でもよい。

## 打ち方 (台本の nextMove。状態だけで決まる)
| 状態 | 手 |
|---|---|
| 狙いが 1 つも無い | カオスオーブ |
| サフィックス 3 つで未完成 | 消去のオーブ (お告げ無し) |
| レアリティ T1 が無い (系統が空き) | 右側の高貴のお告げ + 素の高貴 (通常 / 上級を比べた) |
| レアリティ T1 がある (か、レアリティの系統が低い段で埋まっている) | 無い方 (キャストスピード → 全耐性の順) を カタリスト 20 個 (品質 20%) + 触媒の高貴のお告げ + 右側の高貴のお告げ + 高貴 (通常 / 上級 / 完全を比べた) |
| 狙いの系統が低い段で埋まっている | もう片方を狙う。両方埋まっていれば消去 |
- キャストスピード = 軽快のカタリスト (タグ speed)。全耐性 = **トゥルのカタリスト** (全耐性のタグは fire・cold・lightning・elemental・resistance。「耐性」だけのカタリストはゲームに無いので、元素の 3 つのうち一番安い冷気)。
- 枝 2・3・4 はこの表で自然に分かれる: 2 = レアリティ先 (触媒でキャストスピード → 全耐性)、3・4 = キャストスピード / 全耐性先 (素の右側の高貴でレアリティを狙い、外れても 3 つまで埋める → 消去)。
- 打ち止め: 1 人 2000 神 (オーナー 10-21「2000 神上限でおｋ、現実的か知りたい」) か 20,000 手。人数は 50 人 (同じく「一旦 50 人でええ」)。**1 割以内には届いていない (平均の 95% の幅 ±20〜29%)**。

## エンジンに無い手
- **無かった**。カタリスト (catalyst_speed・catalyst_cold、手順の 1 個 = +1%)・触媒の高貴のお告げ (品質を全部使う、倍率は CoE の式 1 + 0.2 × 品質)・右側の高貴・消去・ブリーチのエッセンス + 左側の結晶化は全部エンジンで打てた。
- 入口 (engine.ts) に無い物: 始めの形に重み 0 の創生の樹の MOD を置く手段 (startFrom が断る)。今回は stage-core の makeStageMod を直に使った。シミュレーターで「創生の樹のスペルダメージがフラクチャー済み」から始めるなら、ジン部長に startFrom で special の置き場を通す手が要る (ブラック経由でサム開発部長へ)。
- 品質の上限を手で決める手 (`qcap:40`) ではカタリストの上限は上がらない (カタリストは maxQualityOf = MOD の「品質の最大値」を見る)。ゲームどおりなので直しは不要。

## 確かめた物
- エンジンで回した: 上の表は全部 (見張り・自前の式はなし)。
- 外の正解: MOD の名・段・お告げとカタリストの効果は poe2db (調べの元の表)。触媒の高貴の倍率は CoE の式 (エンジン内、catalysing-multiplier.ts)。**この期待値そのものを CoE と突き合わせてはいない**。
