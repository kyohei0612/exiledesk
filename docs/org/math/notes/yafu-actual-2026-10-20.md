## ±30% のずれの原因 (分かった所まで)
- 手 5 (32e938d9、消す・骨・エッセンスをエンジンの stepOutcomes の表に) の後、靴のずれは ±30% → ±20% に縮んだ (#1 +13%・#2 +20%・#3 −20%・#4 −24%・#5 +3%・#6 −2%。check-auto-order.mjs boots)。向きは前と同じ: 耐性が先 → 計算が高い、ドッジ・スピリットが先 → 計算が安い
- **1 手の確率は合っている** (一時の台本で、エンジンの入口 addHitOdds / stepOutcomes と auto-model の置き場の表を同じアイテムで比べた):
  - 完全の高貴 + 右側で耐性 T1 (MS + ドッジ / スピリット): エンジン 10.54% / 計算 10.54%、耐性 1 つ付いた後 7.86% / 7.86%
  - サフィに外れが 1 つある時: エンジン 11.79% / 計算 10.54% (外れの系統が置き場を減らさない近似。計算が高く見る向き = 耐性が先の順番の +13〜20% と合う)
  - 上級の高貴 + 偉大 + 左側 (2 つ付く) でドッジ: エンジン 14.20% / 計算 約 12.9% (2 つ目で 1 つ目の外れの系統を塞がない。これも計算が高く見る向き)
  - 消去・カオスの消し方: 本物のスピリット (エッセンスの MOD) と手 5 の代わりの外れで同じ (ドッジ 50%・残り 50%)
- **⑤ の場面にまとめる時のつぶれはほぼ無い**: 計算の形 360〜790 を場面 150〜195 に書く時、違う手を打たれる形を通る回数は 1 人 0〜0.28 回
- **計算が安い順番 (#3) でエンジンが多く打っている所**: 関門ごとに打った回数 計算 / エンジン = ドッジ 101 / 162・スピリット 6.7 / 12.5・耐性 1 つ目 19.1 / 35.6・耐性 2 つ目 29.6 / 28.8。
  エンジンでドッジが最初に付くまでは 1 人 22 手で、そのあと**消去でドッジが 1 人 5.6 回消えて**、そのたびに関門 1 に戻って取り直している。内訳も 完全の高貴 17.3 / 9.3 回・消去 109 / 69 回・スピリットのエッセンス 11.6 / 6.3 回 (エンジン / 計算)
- まだ分からない所: 1 手の確率が合っていて、場面のつぶれも無いのに、エンジンだけ後ろの関門 (耐性) で消去を多く打ってドッジを失う。次は、場面ごとに通った回数を計算の mc とエンジンで並べる (runQuizOnce に場面の数えを足すか、log から場面を組み直す) と、どの場面で分かれ方が違うかが出る。発現 (戻しありの近似、手 5 の表の外) はこの順番ではほぼ使われていない (計算の発現 0 回) ので外せる

## K2b: 靴 #2 の答え無し 422 人 (常駐の解析君、10-20 夜)
- 原因: この台本の rulesOf が、別名の答え (発現で段の足りない狙いの MOD が出た時、計算は「外れの冒涜」に数えるが ⑤ は「札が段の足りない状態・冒涜あり」に見える) が入る前の写しだった。R = 100 神で靴 #2 の最善手がその場面を通るようになり、des=1・B=1・C=0 で止まっていた
- 直し: 台本の rulesOf を src の auto-rules.ts の rulesFromDetail を呼ぶ形に (アストリッドを差す答えだけ台本で足す)。check-auto-order.mjs に靴の R を変える `BOOTS_R` を足した
- 確かめ (`node scripts/analysis/check-yafu-actual.mjs b0 1000 6`): 5 順番の全部で答え無し 0。#2 はエンジン 101.2・99.7%・**101.8 神** (計算 126.1、ずれ +24%)、前半込み 202.0 神。ほかの順番は上の表と同じ数字。手袋 v1 も同じ (113.4 神・答え無し 0)。`BOOTS_R=100.2 node scripts/analysis/check-auto-order.mjs boots` でも答え無し 0
- 上の表の #2 の行 (70.3 神、答え無しを数えない) はこの数字に置き換わる。エンジンの安い順は #1 77.4 < #2 101.8 < #3 206.4 < #5 254.0 < #4 284.6 (計算の順と同じ)
