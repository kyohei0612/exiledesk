## 形
- 元は main。今の本番 (v0.1.595 = b73f5d82 の形 + 当てた物) と**見た目・挙動がそっくり同じ**になるように、本番に出していない物はスイッチで隠す (revert で抜かない)。
- スイッチは 1 か所 (デザイン部長が作る、例 `src/web/release-flags.ts`)。本番のビルドで切れて、開発版 (`preview:prod -- --dev`・dev サーバー) では入る。OK が出たら 1 行で入れる。
- 隠す物: シミュレーター (ツリー)・デイリーと、そこへつながる UI 全部 (タブ・ボタン・リンク・「シミュで開く」の類・案内の文・URL の ?page= で直に開いた時も)・チュートリアルの OK 前の物・docs/pending-release.md の表の物全部 (OK が出た物は入れたまま)。

## 順番
1. デザイン部長: スイッチの仕組み + 画面をまたぐ物 (タブ・ページの入口・デイリー・シミュ・ModeTabs・fitZoom・use-dismiss・段の表を閉じる) を隠す。
2. 各部長が自分の持ち物の OK 待ちをスイッチの下へ: ジン部長 (お告げの欄・アビスのサフィックス・スキルの +・タリスマンの重み・DNT ベース・ルーンの強さ・フォント)、エミュ部長 (聖別の帯・モンキーの直し・ベースのページの選んだ見た目)、シミュ部長 (チュートリアルの d1c97969・コース)。
3. サーバー管理人: スナップの照らしの台本。本番 exiledesk.com と手元の本番環境 (`pnpm preview:prod`、1460) を、同じページ・同じ操作・PC (1660×860) とスマホ (375×812) で撮って比べ、違う所を一覧にする。違いが 0 になるまで 2 と回す。
4. 最後: 違い 0 になったら、聞き直さずに本番に出す (オーナー 10-24「修正後リリースでおっけー」)。出すのはブラックが決めた人が最終チェック長の手順で。人が少ない時期なので、出した後の不具合は報告が来てから直す。
