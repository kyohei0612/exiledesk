# docs/org の決まり (commit f6bcb847、2026-10-20)

## black/README.md
1. コード・データ・計算は自分で触らない。作業は必ず部長・係の新しいセッションへ (start_session)。
2. 調べものも自分でせず、その部・係に頼む (オーナー 10-20)。読むのは返事に要る少しだけ。
3. 「はい / おけ / うい / OK / 進めて / いいよ」= その場で回す、聞き返さない。「ここでやって」の時だけ自分で。「待って / まだ / いったん置け」= 止めて残りとして覚える。
4. 仕事は下の振り先の 1 つの部へ。2 つにまたがる物は部ごとに分ける (境目は開発部)。
5. 聞くのは 1 つ「回していい?」。案が複数ならおすすめを先頭に。
6. 回したら 1 行で伝えて会話に戻る。結果は 1〜2 行、数字・画面・本番は確かめてから伝える。
7. 新機能・思いつきは提案止まり。外に出る物は今の決まりどおり。
8. 同時の裏セッションは 3 つまで。同じファイルを触る作業は順に。
9. 頼む時は完成の形 (何が変わる・どのファイル・何で確かめる) と「docs/org/<部>/README.md を先に読め」を書く。

## dev/README.md
1. 始める前に完成の形を 3 行 (何が変わる・どのファイル・何で確かめる)。書けなければ聞き返す。
2. 読む物は自分の md の地図から。grep・台本で絞り、絞った物は抜き出しでなく全部読む。
3. 数字は台本で出す (手で写さない)。報告の数字は出した台本の場所と一緒に。
4. 直しは小さく 1 つずつ、そのたび型チェック。周りのコードに合わせる。
5. リファクタと機能は別のコミット。整理は触った所の周りだけ、使わなくなった物はその場で消す。
6. 他の部の持ち物は直さない。要る時はどの部のどのファイルかを書いて返す。
7. 境目 (下の地図) を変えたら、使っている部を報告に書く (ブラックが知らせる)。
8. 報告は 3〜5 行: 変えた物・確かめた物 (見張り / 外の正解 / 画面)・残り。
9. 仕事の終わりに自分の md の地図を直す (ファイルが増えた・消えた・動いた時)。

## emulator/README.md
1. ゲームの決まりは書いてある効果どおり。棚の条件は乱数に関係ない物だけ、上限を決めない。
2. カレンシー固有の処理を書き足さず、spec/ の部品とお告げの効き目 (`OmenEffect`) で表す (ADR-004)。
3. MOD の置き場・重み・段はエンジンの行 1 か所。`m.family` を直接比べない、段の重みを自分で足さない (mods/mod-rules.ts)。
4. MOD に固定値は無い (+1 も stat の値)。タグ・品質を触る時は暗黙も。
5. 確率の表を変えたら打った結果と突き合わせる (tests/held-odds-parity.test.ts)。数字の正しさは解析君に頼んでよい。
6. 結果の見張り (currency-spec-golden) をわざと変えた時だけ `GOLDEN_WRITE=1`。

## simulator/README.md
1. 開発版だけ (`SIM_LOCKED`)。本番に出すのはオーナーが決める。
2. 自動でやる打ち方の決まりは必ず画面に文で出す (メモ feedback-show-sim-rules)。
3. 両側の「どれか」は側ごとに分ける (sim-split-by-side)。工程ごとに 1 ページ、初心者でも分かる形 (sim-step-pages)。
4. 10-20 の決め: フラクチャーは完成品の MOD の印・何でも良い枠と妥協は無し・上限は作り直しの回数 (sim-decisions-2026-10-20)。
5. 値段は手入力 + 検索を開くボタンだけ、取引所の自動取得は使わない (sim-no-trade-fetch)。
6. 打つ処理・確率はエミュレーターの部品を使い、自分で書かない。最善手・期待値の数字は解析君に頼む。

## math/README.md
1. 計算の数字はエンジンで回した結果と並べて出す (ずれの % も)。片方だけで「合った」と言わない。
2. 近似を使ったら中身 (何を同じ扱いにしたか) を書く。
3. 外の正解は CoE (確率)・poe2db (重み・置き場)・実測 (メモ craft-weight-sources)。
4. 乱数は mulberry32 (LCG は偏る)。自動の打ち方には上限を付ける (堂々巡りで膨らむ)。
5. 残す台本は scratchpad に置きっぱなしにせず scripts/ に移すか、メモに場所を書く。

## analytics/README.md
1. 24 時間見張らない。小さな常駐の台本が来た時だけ起こす (仕組みは下調べ中)。
2. 毎朝 9 時の日報を読み、気になる所だけ 1〜3 行でブラックへ。
3. バグは即調べ、再現手順 (開発版の URL・押す順) とどの部か (black/README.md の振り先) をブラックへ。自分では直さない。
4. 「おかしい」と言われたら先に記録 (D1・画面のエラーの全文・history) を読む。
5. 要望・バグの返事は直した後のリリースの時だけ、ブラック経由でオーナーの OK の後 (メモ feedback-replies)。
6. 記録を足す時は画面から `logRecord` を呼ぶだけ。KV は増やさない (メモ analytics-logs)。
7. 個人の情報は持ち出さない。記録しない端末 (forget.ts) は集計から外す。
