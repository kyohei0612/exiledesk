# AI の組織 (ExileDesk)

オーナーと話すのはブラックだけ。ブラックが振り分けと順番を決め、部長に直接頼み、部長の報告もブラックへ直接 (オーナー 10-21)。部長は呼ばれたら常駐 (初めて仕事が来た時にブラックが立て、そのブラックの間は開きっぱなし)。一覧に並ぶのは部長 1 人 1 本 (同じ部長のセッションを 2 本立てない。部長の中で分けたい時はサブエージェント、別のセッションの一時の係はブラックが立ててよい、題「<部>；<作業名>」・常駐は付けない・終わったらブラックが閉じる)。同じファイルの仕事は同じ部長に順に (階段式)、ぶつかる時はブラックが順番を決める。本番に上げる時の最後だけ最終チェック長をブラックが立てる。コード (src/ など) の置き場は docs/org/owners.txt と docs/ARCHITECTURE.md の「部ごとの持ち場」。

```
オーナー
└─ ブラック (司令塔・振り分け・順番)   black/
   ├─ リサーチ長 (外の調べもの)        research/   … コードは触らない
   ├─ ジン部長 (エンジンの管理者・共通の部品・英語、画面は持たない) emulator/
   ├─ エミュ部長 (エミュの画面の UI/UX、エンジンに触れない) emu/
   ├─ シミュ部長 (シミュの画面の UI/UX・チュートリアル、エンジンに触れない) simulator/
   ├─ 解析君 (計算の係)                math/
   ├─ 分析君 (要望・バグ・記録・サーバー) analytics/
   ├─ 動画編集長 (YouTube チャンネル「チョコバナナ」) video/
   ├─ 記事編集長 (ブログの記事の仕上げ・図・見た目) blog/
   ├─ デイリー部長 (デイリークラフトチャレンジ、別ページ) daily/
   ├─ 最終チェック長 (本番に上げる時だけ) dev/ … 全部の部の決まりもここ
   └─ ホワイト (ブラックの秘書。毎朝 1 回、md・コードの荒れをブラックに教えるだけ、何も直さない) white/
```

## 流れ
- 仕事: オーナー → ブラック → 部長 (SendMessage)。頼む時は完成の形と「docs/org/<部>/README.md を先に読め」。
- 報告: 部長 → ブラックへ直接 (SendMessage 2〜5 行)。中身は md (その部の todo.md・notes/)。
- 触っているファイル: dev/touching/<部>.md に各部長が始める時に自分で書き、自分の commit で消す。ぶつかる時はブラックが順番を決める。
- 開発版 (deploy:web-dev) と自分の commit の push は、その仕事をした部長が開発ついでにやる。本番 (版上げ・更新内容の日英・deploy:web) はオーナーの OK の後、ブラックが最終チェック長を立てて頼む。
- 今の常駐の宛先 (session id) は dev/todo.md。
- 立てる: ブラックだけ、オーナーの発言のターンだけ (合図で起きたターンでは立てられない)。要りそうな部長は先に立て、途中で要る時はカード。
- 立て直す: 決まりを守れない常駐・重くなった常駐は、todo.md・notes/ に引き継いでアーカイブし、新しいセッションで常駐し直す。
- ブラックを替える時: 手の空いた常駐は引き継いでアーカイブ、仕事の途中の部長だけ残して宛先を新しいブラックへ。
- 言葉: 部長どうし・ブラックへの報告は英語でもよい。オーナーに出る物 (画面・更新内容・ブラックの返事) は日本語 (英語版は別に)。

## 各フォルダーの中
- `README.md` … 決まり (10 行まで) と地図。始める前にここを読む (dev/README.md の「全部の部」の決まりが先)。
- `todo.md` … やる事・OK 待ち。常駐を入れ替える時の引き継ぎもここ。
- `notes/` … 終わった仕事の記録 (設計・調べ)。裏セッションの共有メモも終わったらここへ写す。
