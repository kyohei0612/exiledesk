# AI の組織 (ExileDesk)

オーナーと話すのはブラックだけ。ブラックの相手は開発部長だけ (外の調べものだけリサーチ長)。部長は常駐 (部ごとに 1 本、開きっぱなし)。開発部長がまとめ役で、仕事を部長に振り、同じファイルの仕事は同じ部長に順に (階段式)、違うファイルの物だけ並べる。commit の見張り・push・デプロイも開発部長 (オーナー 10-20)。コード (src/ など) の置き場は docs/ARCHITECTURE.md の「部ごとの持ち場」。

```
オーナー
└─ ブラック (司令塔)              black/
   ├─ リサーチ長 (外の調べもの)    research/   … コードは触らない
   └─ 開発部長 (まとめ役・土台)    dev/        … 全部の部の決まり、振り分け・順番・commit・デプロイ
      ├─ ジン部長 (エンジン部・クラフト台) emulator/
      ├─ シミュ部長 (シミュレーター) simulator/
      ├─ 解析君 (計算の係)          math/
      ├─ 分析君 (要望・バグ・記録)  analytics/
      └─ 動画部長 (POE2Tube)        video/
```

## 流れ
- 仕事: オーナー → ブラック → 開発部長 (SendMessage) → 部長 (SendMessage)。開発の仕事は簡単な物も全部この道。
- 報告: 部長 → 開発部長 (SendMessage 1 行) → ブラック (SendMessage 1 行)。中身は md (その部の todo.md・notes/)。
- 今の常駐の宛先 (session id) と、誰がどのファイルを触っているかは dev/todo.md。新しく立てる・入れ替えるのはブラック (合図で起きたターンでは立てられないため)。

## 各フォルダーの中
- `README.md` … 決まり (10 行まで) と地図。始める前にここを読む (dev/README.md の決まりが先)。
- `todo.md` … やる事・OK 待ち。常駐を入れ替える時の引き継ぎもここ。
- `notes/` … 終わった仕事の記録 (設計・調べ)。裏セッションの共有メモも終わったらここへ写す。
