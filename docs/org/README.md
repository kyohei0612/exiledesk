## 流れ (決まりは番号、ここは段取り)
- 仕事: オーナー → ブラック → 部長 (SendMessage)。頼む文の型は G-23、「docs/org/<部>/README.md を先に読め」を入れる。
- 報告: 部長 → ブラックへ直接 (G-26b の f)。中身は md (その部の todo.md・notes/) と共有メモ (side-session-notes/<ブラックの id>/)、途中の進みは送らず共有メモと commit の題に。止まったら共有メモに書いて待つ。
- 交代: 件数は G-37。決まりを守れない部長・重くなった部長は todo.md・notes/ に引き継いでアーカイブし、要る時に新しいセッションで立てる。ブラックを替える時は、手の空いた部長は引き継いでアーカイブ、仕事の途中の部長だけ残して宛先を新しいブラックへ。
- push と本番: 自分の commit の push はその仕事をした部長 (R-08、出しの最中は R-08b)。本番はオーナーの「出して」の後にブラックが最終チェック長を立てて頼む (R-03・G-38)。
- 今動いている部長の宛先 (session id) は dev/todo.md。
- 共有と各画面の線は U-01、エンジンと画面の線は G-06・G-40・G-41 (エンジンのファイルを書き換えられるのはジンだけ、画面はエンジンの関数を直に呼んでよい・中身を自前で書かない)。
- 言葉: 部長どうし・ブラックへの報告は英語でもよい。オーナーに出る物 (画面・更新内容・ブラックの返事) は日本語 (英語版は別に)。

## 各フォルダーの中
- `README.md` … 持ち場の一言・決まり (設計図の番号を指す、10 行まで)・地図 (フォルダーと入口まで、ファイルの並びは書かない)。始める前にここを読む (dev/README.md の「全部の部」の決まりが先)。
- `todo.md` … やる事・OK 待ち (今だけ。閉じた物は git の履歴)。入れ替える時の引き継ぎもここ。
- `notes/` … 終わった仕事の記録 (設計・調べ)。裏セッションの共有メモも要る物だけここへ写す。
