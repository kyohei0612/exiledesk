# 利用者とその場でやり取りする口・新しい版の「1」の案 (2026-11-09)

頼み: ブラック 68 (オーナー 11-09「あと開発者とリアルタイムで会話できるシステムも考えたい」「要望に対しての返信を今版を上げて送ってるけど結構すぐ返信できるんだよね　あとはこっちが質問したり。ただあっちって更新とかしないとメッセージ届いても気づかないよね」「あと更新したら更新しましたって今やってる人へも通知１みたいな感じで知らせてあげたいんだよな」)。案だけ。作るのはオーナーが選んだ後、本番の設定は Y-75。

## 今の形と困る所
- 返事は KV `fbr:<id>` に 1 件だけ (上書き)。画面は開いた時と 45 分おいて戻った時だけ聞く (`src/state/feedback-replies.ts`)。→ 開いたままの人は気づかない・往復できない・出しに合わせて置いている。
- 新しい版を出しても、開いている人は読み込み直すまで知らない (更新内容は JS に入っていて、古い画面は新しい文を持っていない)。

## 案 A (おすすめ): 新しい版は静的なファイル、やり取りは要望を送った端末だけ数分ごとに聞く
**① 双方向**
- 要望 1 件 = やり取りの列 1 本。D1 に表 `fb_thread` (要望の id・何番目・誰 (`dev` / `user`)・文 2,000 字まで・時刻・`askImage`) を足す (Y-02、KV は増やさない)。今の `fbr:` は読むだけ残し、新しい返事は全部列へ。
- 相手が書けるのは、その要望を送った端末 (要望の `context.uid` と同じ) だけ。画像を後から足す口 (`POST /feedback/<id>/images`) と同じ確かめ。
- オーナーが読む所: 相手の返事は今の要望と同じ Discord のチャンネルに即流す (webhook、もう動いている。スマホに通知が来る)。
- オーナーが書く所: ブラックに「〇〇に返して: …」と言う → 台本 1 本 (`wrangler d1 execute --remote`、オーナーの login で鍵なし、Y-91) で列に 1 行。版も出しも要らず 1 分。→ 画面で決める事 2。
- こちらから質問: 要望を送った人にだけ (id を持つ端末)。送っていない訪問者には誰か分からないので送れない (Y-62)。

**② 届いたらその場で気づく**
- 画面は「返事待ちの列」がある間だけ聞く: タブが見えている間 2 分ごと、隠れている間は聞かず、戻った時に 1 回。最後の書き込みから 7 日たった列・閉じた列は聞かない。
- 届いたら画面の隅の「お知らせ」ボタンに数のバッジ (消えない。押すと列の窓、読んだら消える = メモ feedback-no-transient-notices)。窓の中で返事を書ける。
- 押し出し (WebSocket) でなくても 2 分以内に届く。オーナーの「すぐ」には足りると見る。

**③ 同じ口で新しい版の「1」**
- 出しの作りで `/version.json` (版・出た時刻・その版の更新内容の日英の短い文) を静的なファイルとして置く。静的なファイルは Workers の枠に数えず無料・上限なし (Y-30)。
- 開いている画面は見えている間 5 分ごと (と戻った時) に読み、自分の版より新しければ同じバッジに「1」を足す。押すと新しい版の更新内容 + 「読み込み直す」ボタン (押した時だけ。作業中の物が消える画面なら一言添える)。勝手に読み込み直さない。
- 要望を送っていない人も含め全員に出る。サーバーの回数は増えない。

**④ 枠・費用・荒らし・個人の情報**
- 枠 (1 日 10 万、Y-73 は 1 割以下): 版の確かめは 0 回。やり取りの確かめは要望を送った端末だけで、送った端末 50 台・1 日 1〜2 回 20 分開く見込みで 1 日 1,000 回前後 (枠の 1%)。訪問が 10 倍になっても送った人の数でしか増えない。D1 の読み書きも無料の量の内。**費用 0 円、有料にしない (Y-76)**。
- 荒らし (Y-94): 書けるのは送った端末だけ・今の要望と同じ IP ごと 1 分 1 件 / 1 時間 10 件・1 列に相手の書き込みは 30 件まで・2,000 字まで・bot よけの欄。文は文字のまま出す (HTML にしない)。Discord は誰も呼ばない設定のまま。止めたい列はオーナーが閉じる (1 行)。
- 個人の情報: 新しく取る物は無い。列は要望の id と端末の乱数の番号 (今もある) だけで、IP は列に置かない (数の制限の鍵に一時的に使うだけ、今と同じ)。名前・メールは聞かない。列は 180 日で毎朝の掃除が消す (要望の画像と同じ形)。

**作る量の目安**: サーバー = 表 1 つ・口 2 つ (列を読む / 相手が書く) と台本 1 本。画面 = バッジ・列の窓・`/version.json` を読む所 (デザイン部長)。出しの作り = `/version.json` を書く 1 か所。

## 案 B: Durable Objects の WebSocket で押し出す
- 開いている画面が 1 本つなぎっぱなしにし、オーナーの返事・新しい版をサーバーから即押し出す (秒で届く)。無料のプランでも SQLite の Durable Objects と眠らせる WebSocket は使える。
- 良い所: 届くのが秒。聞きに行く回数が無い。
- 困る所: 開く人全員がつなぐので 1 訪問 1 回以上 Worker が動く (今の訪問 100 で数百、10 倍で数千。枠の内だが案 A の版の確かめ 0 回より多い)・スマホは裏に回すと切れて、つなぎ直しの作りが要る・置き場の種類が増える (Y-02 の決め直し)・確かめの手が多い。
- 案 A で足りなければ、やり取りの列だけを後から B に替えられる (列の表と窓はそのまま使える)。

## 画面で決めてほしい事 (オーナー)
1. 案 A でよいか (2 分ごとで足りるか、秒で欲しいか = B)。
2. オーナーが書く所: (イ) ブラックに言って台本で置く (おすすめ、すぐ作れる) / (ロ) 本番の隠しページで自分で書く (守り方を別に決める: Cloudflare Access で自分のメールだけ、無料) / (ハ) Discord から返す (Bot に書かせる、Y-46「読むだけ」の決め直し)。
3. バッジの場所と形: 今の「お知らせ」ボタンの右上に赤い丸の数 (返事の数 + 新しい版の 1) でよいか。PC とスマホで 1 か所ずつ A/B で見て決める。
4. 新しい版の窓で「読み込み直す」を押すと作業中の手順が消える画面がある時、残すか (残す作りは別の手間) / 一言の注意で済ますか。
5. 相手が自分から書けるのは「こちらが返事・質問した列だけ」にするか、送った要望ならいつでも書けるか。
