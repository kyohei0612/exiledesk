# ブラック のやる事

## やる事
今動いている物 (v0.1.686 の出し・ExileCon 1 日目の文字起こし・? の説明文の箇条書き) が全部終わってから取り掛かる (オーナー 11-09「これ全部終わってから取り掛かる」)。

1. **db とパッチノートの毎朝の見張り** (オーナー 11-09「リリース後の動きだけどさ、dbとパッチノートを毎朝チェックして追加情報がないかスケジュールしておかないとだよね　どういう形でやればいいのかタスクしといて」)
   - 狙い: 1.0 (12-11) の後、poe2db の MOD・ベース・カレンシーと公式のパッチノートに足し・変えがあればすぐ拾って、ジン (データ・決まり) に回す。
   - 決める事 (案を作ってオーナーへ): ① 何を見るか = poe2db (MOD・ベース・カレンシー・ルーンフォージの頁の差分)、公式のパッチノート (フォーラムの告知)、手元のクライアントの書き出し ② どう回すか = 毎朝の予定のタスク (今の「毎朝 9 時 AI 分析」と同じ形) で前の日の写しと比べ、差分だけを md に ③ 誰が見るか = 差分があればリサーチ長が要点 → ブラック → ジン、無ければ 1 行 ④ 外の API は叩かない・公開の頁だけ (Y-52)、取りすぎない間隔。
   - 先に見る物: 今の予定のタスク (毎朝 9 時の AI 分析)、`data-cache/poe2db-*` の写しの取り方、メモ poe2-client-data-source・feedback-verify-with-poe2db、設計図 E-01〜04・Y-52。
2. **開発者とリアルタイムで会話できるシステム** (オーナー 11-09「あと開発者とリアルタイムで会話できるシステムも考えたい」)
   - 相手はサイトの利用者 (要望を送った人)。オーナー 11-09「要望に対しての返信を今版を上げて送ってるけど結構すぐ返信できるんだよね　あとはこっちが質問したり。ただあっちって更新とかしないとメッセージ届いても気づかないよね　ちょっと違和感てきなあれ」
   - 今の形 (R-20・メモ feedback-replies): 返事は server/live の KV `fbr:<id>` に置き、画面は開いた時と 45 分おいて戻った時だけ聞く → 開いたままの人は気づかない、こちらから質問もできない、出しに合わせて置いている。
   - 決める事 (案を作ってオーナーへ): ① 双方向 (こちらの質問・相手の返事、要望ごとのやり取りの列) ② 届いたらその場で気づく (開いている間は数分ごとに聞く / Durable Objects の WebSocket で押し出す、画面の隅にバッジ・小さな知らせ) ③ 返事は出しと切り離していつでも置ける (置く手順を短く) ④ Cloudflare の使用量 (サーバー管理人の見張り)・送れる人の制限 (要望の id を持つブラウザだけ)・荒らし対策。
