## 決まり (docs/org/dev/README.md の決まりが先)
1. 線引き: 結果が変わる物 (付き方・確率・固定される MOD・打てるか) はエンジン、見え方と操作 (いつ使うか・どう見せるか) は画面 (例: フラクチャールートの「必ず成功」はエンジンの for-sim の機能、木のどの手で使い「✦ 確定」と見せるかはシミュ。オーナー 10-23)。
2. 置き場と窓口: 核 (両方が使う土台 = MOD・カレンシーの付け方・お告げ・ゲームの仕組み) は窓口 `engine.ts`、エミュの要望の物は `for-emu/` → `engine-emu.ts`、シミュの要望の物は `for-sim/` → `engine-sim.ts`。要望の物は出した側だけが使い、両方が欲しくなった物はブラックが決めて核へ上げる (2 つの窓口に同じ名前を並べない)。核は for-* を読まず、for-emu ⇄ for-sim も読まない。窓口は名前を並べるだけ (`export *` の束ねを作らない)。
3. 元からある物はそのまま呼ぶ: 核にある関数の写し・言い換え・包み直しを作らない (オーナー 10-23「元からエンジンにあった物をシミュが勝手に自前で作っただけ」)。画面の部長の要望はブラック経由で受け、窓口の形を変える時は使っている部を報告に書く (ブラックが知らせる)。
4. 確かめは小さく: 「エミュの画面の同じ所と同じ答えか」を見る (何万通りの並べはしない)。確率の表を変えたら打った結果と突き合わせる (tests/held-odds-parity.test.ts)、結果の見張り (currency-spec-golden) はわざと変えた時だけ `GOLDEN_WRITE=1`。数字の正しさは解析君に頼んでよい (ブラック経由)。
5. ゲームの決まりは書いてある効果どおり。棚の条件は乱数に関係ない物だけ、上限を決めない。poe2db とエンジンが食い違い写しで決まらない物は poe2db に合わせ、聞かない (オーナー 10-20)。
6. カレンシー固有の処理を書き足さず、spec/ の部品とお告げの効き目 (`OmenEffect`) で表す (ADR-004)。
7. MOD の置き場・重み・段はエンジンの行 1 か所。`m.family` を直接比べない、段の重みを自分で足さない (mods/mod-rules.ts)。
8. MOD に固定値は無い (+1 も stat の値)。タグ・品質を触る時は暗黙も。
9. 画面 (src/views・src/state/emulator・simulator) と部品 (src/components・for-share・見た目) は直さない。要る時はどの部のどのファイルかを書いてブラックへ。
10. 常駐・報告・触るファイル (dev/touching/emulator.md)・push と開発版は dev/README.md の決まり 1・2・5・8 のとおり。本番は最終チェック長。
- (10-23 README の決まり 2 から外した文) 置き場は窓口と同じ名前 (engine-emu/・engine-sim/)、「for-」は画面の部品の for-share だけ (オーナー 10-23)。
